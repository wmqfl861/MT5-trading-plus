### 2.2 T209 网关不拉起终端（D111）

范围：`src/mt5gw/connection.py`、三个入口脚本的启动段、一个看护脚本、测试。

1. **不拉起终端**：
   - 调 `initialize` 之前先确认终端进程在运行（按配置的 `terminal_path` 比对映像路径）。不在就抛 `NotConnectedError` 的一个子类，不调 `initialize`。启动时的 `connect()` 和重连走同一条路。
   - 探测必须在进程内完成（ctypes），不得起子进程：worker 起的任何子进程都会进它的进程树，被 supervisor 拒绝。
   - 探测做成可注入的接口，测试用替身。
2. **启动时终端没就绪按断线处理**：不写 fatal halt，进入和 T141 相同的降级等待（有心跳，有 `DISCONNECTED` 段），连续 15 分钟仍以 78 退出。这样全灭之后的恢复不需要人工清 halt。
3. **`trade_allowed`**：运行器每个决策轮读一次 `terminal_info()` 的 `trade_allowed` 和 `tradeapi_disabled`。不允许交易时本轮不开仓，状态变化时各发一条 `ALGO_TRADING_DISABLED`（恢复时一条）。这个告警在正式检查里定为异常类。
4. **终端看护**：`scripts/ops/terminal_keeper.ps1`，由独立的计划任务每分钟运行，终端进程不在就启动它，别的什么都不做。它只启动进程，不连接终端接口，不违反 D82。
5. **日报等一次性脚本**用同一个网关，自然不再拉起终端；加一条测试钉住。
6. **告警定类**：
   - "终端进程不在"要归记录类，时长并入降级统计，交易日累计超过 1800 秒照旧判失败。可以新增 `TERMINAL_DOWN`，也可以沿用现有的断线告警并在消息里写明原因。
   - 注意 T210 的分类是按消息里的异常名匹配的（`NotConnectedError` 等）。新的异常子类名会出现在 `BROKER_UNAVAILABLE` 的消息里，不同步 `demo_check.py` 的匹配，终端一停就会被判成异常。加一条测试钉住。
   - `ALGO_TRADING_DISABLED` 归异常类。
   - 守卫测试 `tests/test_formal_alert_classification_guard.py` 同步。
7. **验收**：
   - P23-2 的网关一半翻转（终端退出后 `initialize` 调用 0 次）；
   - 演练 C（§4）通过；
   - T201 的全部测试保持绿。

### 2.3 T212 supervisor 的"无法判定"（D115）

1. `verify_deployment` 里的 git 调用超时或起不来，结果记为"无法判定"：
   - 不发 `SUPERVISOR_REFUSED`，发 `SUPERVISOR_DEFERRED`，本轮不做任何重启；
   - 进程树和心跳的只读检查照常做。四个角色都健康，就不写 halt；发现有角色缺失或失活，照旧写 halt（保护不延后），重启留到核验成功的那一轮；
   - 连续三次无法判定，升级为拒绝。
2. 降低开销：`.git/HEAD` 的内容和索引文件的大小、修改时间都没变时，沿用上次"干净"的结论；完整的 `git status` 至多每 15 分钟做一次。SHA 比对每轮照做。**要重启任何角色的那一轮，必须先做一次完整核验，不用缓存**——"只重启干净、钉死的部署"这条性质不能因为缓存而变弱。
3. git 和 powershell 用绝对路径调用（C23-5）。
4. `SUPERVISOR_DEFERRED` 在正式检查里定为记录类，守卫测试同步。SHA 不符、工作树不干净、非 Demo 配置照旧拒绝、照旧判异常。
