## 1. 规则增补（第十六轮）

- **单一执行方**（D64，用户指定）：只有一个会话可以对 Demo 做重启、清除 halt/pause、演练和部署。其他会话只读，只写报告。各会话用不同的 git 身份（例如 `zcode-main`、`zcode-scheduler`）。main 只由主会话写入；调度会话的日志改为提交到 `ops/phase-f-log` 分支，由主会话合并。
- **实质有效性清单**（D66–D68、D70）：每个研究批准点的材料与裁定都必须回答以下问题：
  1. 被检验的代码与将来交易的代码是否同一份？
  2. 数据粒度是否与定义一致（按根数定义的窗口在该数据上是否仍是原含义）？
  3. 按发表后的效应量，达到 50% 检验力需要多少年？锁箱能否区分有效与无效？
  4. 是否依赖免隔夜费？
  5. 彩排是否跑通？耗时多少？
- **裁定篇幅**：≤ 2 页。机械检查只附自动命令的输出（T170），不再逐项手抄哈希。
- **新模块**：超过 300 行的新文件，在提交说明里写明为什么不能在原位修改（D71）。

## 2. 任务

### P0 实盘（维护窗口前完成离线部分）

#### T140 确定态拒单不退出

1. 在 `mt5gw.errors.RETCode` 补充 10013（INVALID）、10020（PRICE_CHANGED）、10021（PRICE_OFF）、10024（TOO_MANY_REQUESTS）等确定态码及中文描述，并更正 10031：MQL5 文档中它是 TRADE_RETCODE_CONNECTION（与交易服务器无连接），不是"客户端禁止此类交易"（O16-7），按断线处理（T141）。
2. 执行器对 `TradeRejectedError` 的处理：
   - journal 记 rejected、写 confirmed 意图（保持现状）；
   - 然后返回 `RoundReport(action="rejected", error=...)`，不再重抛；
   - 写告警 `ORDER_REJECTED`（含 retcode）；
   - 本 bar 内不再重试。
3. 同一 magic 连续 3 个 bar 被拒时，写 `pause-<magic>.json`（reason=`order_rejected_streak`），只暂停该策略；人工确认后解除。
4. `OrderResultUnknownError`（状态未知）保持退出，交给重启核对。
5. 测试：
   - 假网关返回 10021 → 进程不退出，心跳继续，下一个 bar 正常决策；
   - 连续 3 次 → 只暂停该 magic；
   - 状态未知 → 仍然退出。

**验收**：P16-3 变为 NOT-REPRODUCED；全量回归绿；CI 绿。

#### T141 断线不退出

1. 下单路径上的 `NotConnectedError` 与查询路径同样处理：本轮 `blocked_broker_unavailable`，不开新仓，写告警。
2. 网关内有界重连：指数退避 5、10、30、60 秒，单次调用仍受 T110 的期限约束。
3. 风控、对账进程同样处理断线。连续 15 分钟连不上才以专用退出码退出，交给 supervisor。
4. 测试：
   - 假网关断线 3 分钟后恢复 → 三个进程都不退出，恢复后照常；
   - 断线 20 分钟 → 以专用码退出，并留下标记。

#### T142 风控、对账进程的异常分级与取证

2. 读取 11-05 16:15（风控）、11-06 11:22（对账）的 `.log.err` 与退出标记，把结论写进 phase-f-log 的"取证补记"；查不清就写"无法确定"。
3. 测试：注入 `PermissionError`（11-01 的签名）→ 风控不退出；连续 5 次 → 退出并留下标记。
