## 2. 工作规则（取代 D54 的双会话规则）

**角色**：本会话是主会话（管理员角色），唯一写 main 的执行方。

- 外部会话（全局审核、PR 复审）只出报告或 PR，由本会话审阅后合并。
- 合并外部 PR 用本地 `git merge --no-ff`，然后直推 main。research-allowlist 对管理员路径失败是设计行为：不改该工作流，不为让 PR 变绿而削弱任何检查。

**提交**：

- 一个提交只属于一条线，说明带前缀：`[H]` H 线、`[P]` P 线、`[S]` 共用底座、`[OPS]` 运维与日志、`[DOC]` 纯文档；
- 只 `git add` 本任务改过的文件；
- 不用 `git add -A`。

**推送（每次都按这个顺序）**：

1. `git fetch origin && git rebase origin/main`（或 `git pull --rebase`）；
2. 同步之后跑全量回归，退出码显式捕获，不经过管道（第十四轮 L7）；
3. 推送；
4. 确认 GitHub Actions tests 为绿，再勾复选框。证据写 main 上的提交号加 tests 的 run_number。

CI 红时停止推送新功能，先修红。

**并行（D62）**：H、P 两线用多个开发子代理并行，各代理使用独立 worktree、明确模块和文件所有权；共享文件的合入由主会话串行处理。每个模块完成后交未参与实现的独立子代理审核，阻塞问题修复并复核后，主会话按上面的同步→全量回归→推送→CI顺序交付。生产数据与部署状态不在开发 worktree 间共享写入。

**实盘安全**：

- 只允许 `-Mode Demo`、0.01 手；真实账户的连接与下单一律禁止；
- 不热改正在运行的 Demo，部署只走 runbook 的维护窗口；部署记录写 SHA、PID 和起止时刻；
- Demo 从独立的部署 worktree 运行，固定在发布 SHA（见 T111b）。开发目录里的 pull、merge、切分支不得影响运行中或重启后的代码；
- 正式窗口内不改实盘代码（`src/mt5live/`、`src/mt5gw/`、`scripts/live_*.py`、`scripts/risk_process.py`、`scripts/demo_run.ps1`、`demo-configs/`），改了就按 D57 重新起算。

**研究纪律（铁律 16–22 照旧）**：

- 研究运行必须属于已批准、已开启的轮次；
- 不在真实事件或真实触发上计算任何收益或结局来"看看"；可行性筛查只允许数触发和算成本；
- 预期效应只能来自文献，P 线另可来自发现段；
- 判定规则先写后跑，失败不换种子重跑，不事后改阈值。

**批准点（D62）**：提交具体材料，暂停依赖该批准的下一步并交独立审核子代理。结论应明确 approved / conditional / rejected、对应提交或材料哈希、适用范围与未决条件；approved 或 conditional 的条件全部闭合后继续。

### P1：H 线研究

#### T112 事件模式的信号驱动方向、H 线合并数据与覆盖一致性

**依据**：第十五轮 H15-1、H15-2、H15-5。

**步骤**：

1. **跨品种信号字段**：
   - 候选登记 `[declared]` 新增 `signal_symbol`（可选，缺省等于成交品种）与 `side_rule`，取值 `static_long`、`static_short`、`mtd_sign`；以后需要新的规则，按版本新增；
   - 轮次 `[evaluation]` 必须重复声明 `side_rule`，两处不一致时拒绝开轮。
2. **事件分支**：
   - `_v3_gate_evaluate` 的 `side_fn` 按 `side_rule` 逐事件计算方向。`mtd_sign` 的信号窗口按候选登记的定义取，只用事件入场之前已收盘的数据。C002 登记的窗口是"上月倒数第二个交易日收盘 → 本月倒数第二个交易日收盘"（Melvin 与 Prins 的口径）；现行 B7 用的是"上月最后一根收盘 → 事件日前一日收盘"，与登记不一致，一并改正；
   - 随机化零分布里的随机事件，用同一规则在随机时刻计算方向；
   - `--event-side` 只在 `side_rule` 为静态时允许，且必须一致，否则在任何计算之前拒绝。
3. **H 线读合并数据**：`cmd_screen`、`cmd_gate` 对候选预筛计入外部段的品种（含信号品种）用 `merged_research_series` 读取（X-03 契约），外部段点差按 ×1.5 绑定，source tags 写进运行记录。
4. **覆盖一致性**：
   - 运行前只看时间戳，计算实际覆盖（年数、事件数、按来源分段），与候选最新预筛的覆盖比较；
   - 实际年数低于预筛的 90% 时拒绝运行，提示重跑预筛；
   - 实际覆盖写进台账运行行与关卡报告。
5. **bar 级跨品种**：`signal_symbol` 不等于成交品种的策略，研究运行在没有提供多品种 bar 时拒绝（B7 的"同序列近似"只允许作为 G0 与诊断）；试验身份与 G0 覆盖信号品种的数据哈希。
6. **测试**：
   - 合成数据上，信号驱动均值与静态均值不同，事件分支取到的是信号驱动的；
   - 静态 `--event-side` 与 `mtd_sign` 冲突时拒绝；
