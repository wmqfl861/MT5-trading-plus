## 2. 新增任务

### 2.1 T201 网关重连修复（P0，实盘代码，D87）

改 `src/mt5gw/connection.py` 与 `src/mt5gw/config.py`。完成后 P19-1 应为 NOT-REPRODUCED。

1. `_attempt_reconnect()` 先调 `terminal_info()`（仍在 T110 期限内）：
   - **返回对象**（IPC 通）：
     - `connected` 为真：视为成功，重置退避。
     - `connected` 为假：**不调 `initialize`**，保持 `_initialized` 不变，推进退避，原因写"终端在线、交易服务器未连接——等待终端自行重连"。
   - **返回 None**（IPC 不通，例如终端进程不在）：把 `_initialized` 置为假，再调 `initialize`，然后检查 `terminal_info`。
2. `initialize` 一律带 MT5 自己的 `timeout`（毫秒），包括 `connect()` 启动时那一次：
   - 新增配置 `initialize_timeout_ms`，缺省 15000；
   - 校验：1000 ≤ 值 ≤ `query_timeout_s × 1000 − 10000`。
3. **实现陷阱**：
   - `_invoke(name, fn, *args, timeout=None, **kwargs)` 的 `timeout` 是 T110 期限。不能写成 `_raw("initialize", path, timeout=15000)`。
   - 用 `functools.partial(self._mt5.initialize, path, timeout=ms)` 一类的写法，确保值真的传到 `mt5.initialize`。
4. 测试（新文件，假 MT5 模块）：
   1. IPC 通、服务器断：零次 `initialize`，抛 `NotConnectedError`，退避推进；
   2. 随后服务器恢复：通过，不调 `initialize`，退避重置；
   3. IPC 不通：调一次 `initialize`，且假模块收到 `timeout` 关键字、值 ≤ 20000；
   4. 启动时 `connect()` 带 `timeout`；
   5. 配置校验；
   6. T110 与 T141 原有测试全部保持绿。
5. 按惯例做独立审核、合并态全量回归、CI 绿，然后**定版新候选（main + T201）**，记下完整 SHA。部署树用新 worktree。

### 2.3 T203 stderr 告警细分（有条件，检查器，D88）

依据今晚 `23edcff` 影子盘和周六新候选 PaperSoak 的三个 `.log.err`：

- **全空**：不做 T203。
- **只有 Python warnings 模块的行**（`文件:行: XxxWarning: …` 及其下一行缩进的源码行）：检查器把只含这类行的 `.err` 列为记录（输出里逐文件列出），不判失败。其他任何内容仍判失败。测试：只含警告 → 3；警告加任意其他行 → 1。
