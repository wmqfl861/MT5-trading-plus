## 2. 下载与两道闸

### 2.1 规则和执行

纪律（两版相同）：一次一条命令、一条命令一个年份（`--years <单个年份>`，`--pace-seconds 10`）；成功的两次下载之间 `sleep 10`；不并发；不改请求头、代理和 `adapters.py` 的重试参数；不用 `--force`。顺序 GBPUSD → USDJPY → USDCHF → AUDUSD，年份 2003 → 2025。

续做规则（主会话在第一版之后给出，取代"任何一次下载失败就停"）：某年失败后等 60 秒再试同一年，同一年最多试 3 次（含第一次）；3 次都失败就停，不再往后做。任何一次响应是 HTTP 429 或 403，或者拿到的内容不是 zip，看到就停、不重试。"站点没有这一年"的明确信息（404 或等价）记为站点没有这一年，继续下一年。

执行情况：

- 磁盘余量（C 盘，`df -h /c`）：开始前 74 GB（07:24）；GBPUSD 开始前 74 GB（08:02、08:20 两次核对）；停下后 74 GB（08:24）。没有低于 40 GB，也没有走到"每 10 个年份"的检查点。
- 闸门计算串行；下载期间没有跑测试（所有测试都结束于 08:00:06，早于第一条下载命令）。
- 没有连接交易终端：没有 `import MetaTrader5`，没有启动或结束任何终端进程。

形式（`--ext-root` 是顶层参数，写在子命令 `histdata` 之前）：

判读：

| 判据 | 实测 |
| --- | --- |
| 是不是"站点没有这一年"（HTTP 404 或等价信息） | **不是**。下载表单页（GET）取到了 tk，否则到不了 POST；三次响应声明的总长都是 2,265,821 字节。站点有这个文件 |

| 是什么 | 读到一半，流结束了（`IncompleteRead`）。没有看到超时或连接重置的报错 |
| 传了多少 | 读到 1,638,400 字节（72.3%）、2,228,224 字节（98.3%）、2,179,072 字节（96.2%）。三个数都是 16,384 的整数倍（100、136、133）；16,384 是一条 TLS 记录的上限，看起来是整条记录收完之后连接才结束的（推测） |
| 重试了几次 | 每条命令里适配器按既有参数试 2 次，所以一共 6 次内部尝试，都失败了。脚本只打印最后一次的错误：看得到的 3 条都是传输中断，另外 3 条的错误原文看不到 |
| 本机有没有走代理 | 没有（环境变量和系统代理设置都为空），请求是直连 |

三次断在不同的位置（72% 到 98%），不是固定长度截断；第一版里"原因分不清"的判断在续做之后多了一条事实：**同一年份连续 6 次内部尝试没有一次传完**，这不像偶发的抖动。是站点一侧生成这个文件的程序提前结束，还是本机到站点之间有什么在响应传到约 2 MB 时结束连接，从本机看到的错误原文分不出来。按规则，3 次失败就停。

3. **研究年数的疑点**（读代码发现的，没有改）：回收年里被月级闸门丢掉的月份，现有函数只在实测空洞超过 30 天时才切开——`_manifest_gap_intervals` 只认整年。空洞有多长，取决于丢的是哪个月、周末落在哪几天：`_histdata_year_gate` 的回收分支按换算后 UTC 的自然月留行，空洞从上一个月最后一根 bar 到下一个月第一根 bar，下限是那个月的长度加一分钟。
   - EURUSD 已丢的几个月，实测空洞（`data/ext/histdata/EURUSD/M1` 的 `time` 列）：2019-10 是 31 天 00:01，2023-02 至 07 是 181 天，2023-10 是 32 天 03:01，2024-10 是 31 天 00:01。四处都过线，所以现有数字里看不出这个差别。
   - 按这个切法推算（未实测）：30 天的月份留下 30 天 00:01，刚过线；2 月只有 28 或 29 天，空洞贴着月初月末时不过线，这个月仍计在年数里。也就是说，丢掉的月份切不切开取决于日历，不取决于它有没有启用。
   - 四个币对的数据到位后，用现有函数算出来的年数里，如果有丢单个月份的年份，要对照这一点看。
4. **草案 §10.1 第 9 项**：HistData 的批准和锚点条件是否自动覆盖四个新币对，待外部审核裁定。
