## 2. 拟议接口与三层边界

仅描述接口：`check_t121_admission(input_meta, cost_meta, review_binding) -> admission_description`。
三个参数均为调用前已在内存中的有限元数据记录；不接受文件句柄、加载器、回调或可执行对象。
引用是供人工审阅的标识，不作路径解析、文件读取、网络访问、原工件哈希计算或隐式缓存搜索。
接口至多比较声明的用途、范围、身份和条件，不能凭元数据确认实际内容、来源合法性或审核真实性。

| 层次 | 所需材料与责任 | 本接口能够表达的结果 |
| --- | --- | --- |
| 内容身份 | 工件版本、摘要域及 SHA256，与审核对象的提交/文件身份逐项对应 | 缺项、冲突或声明匹配；匹配不证明工件实际未被篡改 |
| 独立审核有效性 | 原独立审核记录、授权归属、范围、条件、时效与撤回状态，经明确的可信协调路径核验 | 保留未核验；调用者自填记录不能成为有效审核 |
| 一次执行许可 | 针对确定操作、版本、范围和一次运行的另外明确放行 | 恒为 `not_released`，无许可签发、消费或执行入口 |

结构可校验、生产适配审核、真实证据审核和一次执行放行是分别完成的步骤，没有自动递进关系。
本批可信来源核验的可接受方式尚未独立决定，因此即使字段齐全、所有声明相符，审核有效性仍是未知。
`approved=true`、`review="approved"`、审核者名字、文件名或貌似正确的 hash 都不能改变上述边界。
将 `synthetic` 改标 `production` 或将真实输入改标合成均不产生证据资格；未知来源保持未知。

## 3. 最小版本与输入元数据

以下字段是待审设计，未知可显式记 `null` 并列缺项；禁止补造默认年份、来源、账户或批准值。
身份引用统一描述 `artifact_id`、`artifact_version`、`sha256`、`digest_domain`；摘要域须区分原始文件字节与 canonical payload。
仓库记录另带 `repo_commit`、`repo_path`，使用完整提交 SHA 与仓库相对路径；外部工件用明确来源版本，不伪造 Git 身份。
这些均是待核验声明：hash 格式合法只说明可比较，不能证明对应字节已读取，也不能把不同摘要域当成相同身份。

| `input_meta` 字段 | 最小含义及拒绝静默推定的规则 |
| --- | --- |
| `contract_version` / `kind` | 前者精确标识本契约版本；后者声明 production / synthetic / unknown，不能用于授权 |
| `purpose` | 明确为 `T121-count-cost`；它是申请用途，不是执行许可，也不覆盖诊断、研究或方法门 |
| `input_ref` / `manifest_ref` | 输入工件与源 manifest 各自的版本身份；不得只给目录名或“最新” |
| `symbols` / `source_timeframe` / `target_timeframes` | 逐项列 XAUUSD、EURUSD 中所申请品种；源 H1、目标 H1/H4 显式列出，不扩池、不跨周期借用批准 |
| `range_start` / `range_end_exclusive` | 本次申请的半开范围，逐品种对应；不从数据实际覆盖反推许可 |
| `discovery_start` / `discovery_end_exclusive` | 经审核的发现段范围；本次上界固定为 2016-05-01 00:00 UTC 不含，不重定正式轮次分界 |
| `source_manifest` | 逐品种列 used=true 的年份、明确来源、来源分段范围与 excluded_months；内容须绑定 `manifest_ref` |
| `scope_review_refs` | 对用途、研究库及源范围的原独立审核引用；没有依据时列缺项，不能借 A2 规则批准代填 |

申请范围须被获准范围、发现段和 manifest 来源分段共同覆盖；used 年份或排除坏月冲突必须显式保留。
范围只比较元数据声明，不扫描 bars、不核验真实 H1/H4 完整性、不统计触发；真实输入资格仍待独立核验。
日期采用带 UTC/offset 的 ISO-8601 表达并按 UTC 比较；不能解析、缺时区或起止倒置均不得静默修复。
半开终点等于固定截止可作为范围声明；纳入截止时刻、终点越界或把排除终点解释为包含均属冲突。
字段类型不隐式转换：布尔值不充整数，字符串不充列表，空引用不充有效身份；未知、空集合和冲突分开记录。

## 4. D50 成本证据逐组件绑定

`cost_meta` 按品种及明确账户用途分组，每组逐一列 spread、slippage、commission、contract、overshoot、swap。
每个组件独立持有下表共同字段；可引用同一来源工件，但不能用一个“整包 approved”代替逐项对应关系。

| 共同字段 | 绑定要求 |
| --- | --- |
| `component` / `symbol` / `purpose` / `artifact_ref` | 组件名、品种、显式申请用途 `T121-count-cost` 与该工件版本及摘要；工件内部有多组件时注明受审段/键 |
| `source_ref` / `observed_start` / `observed_end_exclusive` | 来源记录身份及经验观测期；非观测型固定费表明确类型、发布版本与适用依据，不能省略来源理由 |
| `applies_start` / `applies_end_exclusive` | 费表/模型适用期及其审核依据；不可拿观测期或审核日期替代适用期 |
| `account_scope` / `account_purpose` / `currency` | 原账户的非敏感范围标识、Demo/真实等用途、币种；Demo 字符串本身不能代表原账户身份 |
| `basis` / `units` / `conversion_basis` | 费率口径、单位及需要的转换规则版本；不提供实际费率、合约数值或价格 |
| `review_refs` / `dependencies` | 原独立审核身份及精确受审用途/范围，依赖的其他组件版本；缺依赖不得回落到默认值 |

来源、观测期、适用期、账户用途和 D50 合法性须逐项经独立审核；时间范围声明相符不能单独证明用途合法。
每项用途须与 input_meta 及原审核一致，获准适用期须覆盖申请范围；用途、品种/账户、依赖版本或覆盖不符均列冲突。
非观测型材料的观测期可记不适用，但必须有明确类型与独立依据；未知字段不能伪装成“不适用”以消除缺项。

| 组件 | 应描述的专属口径及现存限制 |
| --- | --- |
| spread | absolute/relative、纽约小时覆盖及 p90/n_days 口径；须有符合 D50 的合法来源与覆盖依据 |
| slippage | spread_fraction/fixed_price/event_hours/event_multiplier 的规则版本，精确绑定所依赖 spread 身份及范围 |
| commission | 来回每手、币种、费表与账户适用性；零佣金也须明确依据，缺记录/默认零不是免佣证明 |
| contract | 每手大小的单位、报价币种、规格版本及适用性；仅有 specs hash 不证明合约数值合法适用 |
| overshoot | version=2 / basis=stop_level、纽约小时 p90/n_days 口径与覆盖依据；缺表不能以零代替 |
| swap | free/charged、原账户范围、币种与适用期；charged 还需方向、计费日/三倍日和转换规则的独立裁定 |

当前 commission、contract、overshoot 及合法 spread/slippage 仍缺完整获准依据，整行维持 blocked / waiting_data。
2026 经验摘要及依赖其点差的滑点仅可披露来源：不得算 1× 或其他诊断、绑定成本或已知分量下限，不参与设计族去留或 T122 判断。
现有摘要即使已有工件、版本或哈希也不改变用途拒绝；本稿不为它计算新绑定或提出例外放行。
Demo/USD free 仅沿 A2 §6 的原账户单项假定；不外推其他 Demo 或真实账户，不补齐其余成本，也不要求补造 charged 配置。
现有 charged 合成入口仅接受有限非正 long/short 费率，底层模型接口更宽；正费率、符号解释和生产格式适配仍待独立决定。
本稿不批准实际 charged 费表、不把合成运算测试当费率依据；p90 继续是冻结情景，不是实际平均成本上下界。

## 5. 独立审核绑定与来源核验

`review_binding.records` 逐份描述原记录：`record_ref`（提交、相对文件、原始字节 SHA256）、审核角色及独立性依据、结论与条件。
每份记录须明确 `reviewed_commit`、受审文件 SHA256/摘要域、所绑定 input/manifest/各成本组件版本、用途及完整范围。
记录另描述 `decided_at`、有效期或其明确适用规则、未决条件、后续替代/撤回记录引用；缺少状态依据不假定永久有效。
如需比较时效，`review_binding.as_of` 是固定参考时刻的声明，来源与及时性也待核验；接口不自行读取时钟或轮询审核状态。
A2 规则批准、A3 未运行报告批准和入口技术 PASS 各有原对象与范围，不能合并成一次生产材料批准。

协调责任仍沿 D62：由主会话汇集版本化材料，交与实现者分离的独立审核者；实现者与主会话不得自批。
“主会话汇集”本身不证明记录可信；须先独立明确可接受的原记录来源、审核者授权归属及核验方法，再由该可信路径核对。
核对必须覆盖原记录内容、受审提交/文件 SHA、目的、品种/周期/账户/时间范围、条件闭合与后续撤回，不能只比一个批准字符串。
`review_binding` 内自填 `verified`、`approved_by` 或 `revoked=false` 仍是调用者声明；本接口不会据此升级审核有效性。
可接受绑定形式、来源验证方式、撤回检索及时性以及 conditional 条件闭合证据如何认定，均待独立决定；本批不建新服务。
缺原记录或可信核验依据列缺项；声明之间不符、明确过期/被撤回、范围不符或条件未闭合列冲突，并同时保留其他缺项。
无法确认撤回状态、时效或条件闭合时保持未知/缺项与 `not_released`，不得把“未见否决”解释为批准。
内容或适用范围变化后原绑定不覆盖新版本；须重新独立审核受影响材料，不能复制旧 approved 字段。

## 6. 返回约定与无副作用边界

| 返回项 | 拟议含义 |
| --- | --- |
| `contract_version` / `material_state` | 契约版本；材料声明状态为 incomplete / conflicted / declared_complete，最后一项仅表示字段声明完整 |
| `missing[]` / `conflicts[]` | 逐字段/组件/记录列原因及对应引用；两者可并存，不以冲突覆盖缺项，不删除问题行 |
| `identity_bindings[]` | 对申请方声明和受审对象声明逐项列 missing / conflict / declared_match；不使用 verified 表示真实内容已核验 |
| `review_validity` / `pending_decisions[]` | 本接口保留 unverified 与需独立决定的问题；审核有效性在接口外另行核验 |
| `execution_status` | 恒为 `not_released`；没有布尔放行键、可执行句柄、加载指令或运行 token |

状态优先显示 conflicted（存在冲突），其次 incomplete（存在缺项），否则 declared_complete；原因列表始终完整。
可信核验尚无依据也属于缺项，因此当前不能由表面字段齐全推导 declared_complete，更不能推导材料获准或可执行。
未来若全部元数据及外部核验引用齐备，declared_complete 仍只是声明一致性描述，不能代替独立审核原结论。
不产生真实触发数、UTC 日数、成本、feasible/fail 或批准字段；未运行值保持未知/null，不能写零或回写旧报告。
任何输入都不加载数据、运行计数/成本/诊断、label/fit、写台账或启动研究；接口也不生成费用模型或审核记录。
现有生产入口的 waiting_data 行为保持不变；未来生产 adapter 的设计与实现须另审，本稿不隐式接通它。

## 7. 有限未来合成验收约定（本批不执行）

仅在后续接口实现另获授权时，用少量固定内存元数据验证下列契约；不新造校验平台，不重跑已完成的合成计数算法测试。

| 合成情形 | 未来应观察的结果 |
| --- | --- |
| 缺用途、范围、manifest 或任一身份 hash | 各自列缺项，不推定默认值；execution_status 不变 |
| 固定合成记录的文件/hash/版本被替换，或摘要域混用 | 已声明身份不一致列冲突；仅改真实字节而元数据未变时不能声称已检出篡改，留给外部核验 |
| 审核明确过期、被撤回或条件未闭合 | 相应冲突与其他缺项并存；未知撤回状态列缺项，不默认为有效 |
| 跨品种、周期、原账户或范围错绑 | 保留全部冲突；Demo free 不覆盖另一账户或其他成本组件 |
| 自填 review/hash/approved/verified，或 synthetic 改标 production | 不产生可信审核或许可；缺原记录/可信路径依旧缺项 |
| 2026 摘要改用途、滑点依赖该摘要或缺必需成本组件 | 保留用途拒绝与各组件阻塞，不做诊断、不生成完整成本结论 |
| charged 正费率、符号或格式适配尚无独立决定 | 明确未决，不沿用 synthetic 限制批准生产，也不擅自拓宽格式 |
| 看似完整且一致的全部材料 | 仅描述声明匹配；review_validity 仍不由自填字段升级，execution_status 恒不变 |
| 截止前、终点恰等于截止、越截止及等价 UTC offset | 按半开范围区分；截止时刻不得纳入，不因表示差异扩大范围 |
| 布尔/整数、字符串/列表、空值及无时区/倒序时间冲突 | 不隐式转换或补齐，分别保留类型冲突与缺项 |
| 同一固定输入重复调用并检查输入前后 | 描述一致、输入不被修改；无文件/网络/数据加载、计数/成本、label/fit 或台账副作用 |

上述是有限验收约定，没有测试实现、执行结果或已通过声明；完整材料情形也不得接真实工件以“验证”。
