```

     │    选题：候选登记（research/candidates/）→ 预筛（文献、持仓周期、事前成本、检验力、机制空缺）
     │          → 研究轮次预注册（research/rounds/R#.toml，看结果之前提交）
     │    检验：卡（属于某个已提交的轮次）→ screen → 关卡 v3（主检验 + 否决项 + 诊断）
     │    台账：哈希链；试验身份 = 卡 + 参数 + 数据哈希 + 成本版本 + 代码指纹；N 按项目级
     │    └─ 候选 ──（管理员批准，计入锁箱预算）──► G5：一次性读主库锁箱段
     │                                       └─► 前向样本：影子盘 / 模拟盘运行 6–12 个月
     │
     └─ 实盘侧（每个策略一条同步链路 + 两个独立进程）
```

## 4. 铁律 v4

1. **时间**：
   - 库内时间是"贴 UTC 标签的 naive datetime"（Exness 服务器为 GMT+0），启动时实测校验；
   - 随夏令时移动的事件一律用交易所本地时间定义（换日 = 17:00 America/New_York），禁止固定 UTC 小时；
   - 配置里的本地时刻写明时区，并有长度上限校验。
2. **金额与手数**：`contract_size` 必填；定手数只有一个函数，回测、关卡、实盘共用，只在开仓时调用；风控只设上限。
3. **只用已收盘 bar**：信号在 bar i 收盘产生，bar i+1 开盘成交。
4. **Bid 基准**：K 线按 Bid；多头 Ask 入场、Bid 出场，空头相反；SL/TP 触发口径与 MT5 一致；跳空穿过止损按开盘价成交。
5. **同一份策略代码，同一套执行语义**：A 层、B 层与实盘一致；实盘不支持的出场规则在启动时拒绝；窗口不变性 ≥100 个随机探针。
6. **锁箱**：全局单一 cutoff，只能更早不能更晚；研究侧只读研究库；每张卡的 G5 只能用一次；整个锁箱有使用预算（D16）。
7. **可复现与试验计数**：
   - 每次运行写独占目录与 manifest，所有运行（含失败）进台账；试验身份含代码指纹；台账带哈希链；
   - **G4 的试验次数 N 按项目级去重计数**（全部谱系），谱系与轮次的 N 同时报告。
8. **权限分离**：研究、审查角色只能新增卡与候选、修改策略库与研究报告；执行点三层：本地钩子、CI 路径白名单、ACL。
9. **安全**：仓库公开——令牌、IP、账号（含模拟盘账号）、服务器名、本机绝对路径、`config.json`、`mcp.json` 不得入库；CI 做敏感信息扫描。
10. **实盘**：LLM 不进交易环路；默认只允许模拟盘；下单路径同步经过风控闸门；停机信号存在或读不出时禁止新开仓，平仓不受限。
11. **回测与实盘的禁入规则同源**：禁止开仓时段、点差闸门只有一份配置。
12. **证据才算完成**：复选框附证据；证据分四级，文档声称的级别不得高于证据；CI 为红时停止推送新功能。
13. **成本敏感性**：隔夜费（0 倍与 1 倍）与点差在 G2 做敏感性检查；成本模型写明样本覆盖。
14. **容差不因结果放宽**：容差只能依据机制设定；放宽须单独说明并经用户确认。
15. **跨进程文件契约**：统一原子写；指令带编号；每策略各写各的文件。
16. **先定规则再开卡**：每一轮研究在看到任何结果之前提交轮次预注册（候选、评估方式、试验计数口径、锁箱用量、推进规则）；`bt` 拒绝运行不属于已提交轮次的卡。
17. **选题有据**：候选必须通过预筛（§6.2），预筛材料写进候选登记表；文献必须包含发表后或样本外证据，并写明检索过的反驳。
18. **检验力先行**：开卡前计算现有数据上的检验力；检验力 < 50% 的候选不开卡，进"待数据"队列。
19. **外部数据同口径**：外部数据入库前与 MT5 数据做重叠期一致性核对（价格口径、时区与夏令时、收益相关、缺口）；来源与版本写进 manifest；同样遵守锁箱 cutoff。
20. **仓位纪律**：禁止马丁、网格、摊平，禁止按连亏或连赢调整手数；每笔交易的风险由定手数函数在开仓时一次确定。
21. **拟合与使用分离**：从数据估计出来的模型（概率表等）只在训练段拟合，产物冻结为带哈希的文件；策略运行时只读文件，不在信号计算里现场统计历史；walk-forward 每个训练窗重新拟合，训练样本的标签窗口不得越过训练窗末端。
22. **概率要能检验**：用于决策的概率必须来自写死的统计规则，并在样本外做校准检验；凭感觉或由 LLM 现场给出的概率不得进入决策。

## 6. 研究方向 v4

### 6.1 六张基线的定位：标定样品

- **定位**：H002–H007 用来校准关卡、成本模型、引擎与实盘链路，不是经过比较挑出的研究候选。它们的结果只作为测量证据，不作为选方向的依据。
- **成本结论**：成本 v3 口径下，日内 M5/M15 族在本经纪商不可行（H003 毛利/成本倍数 1.41）。这一条作为成本结构的测量结论保留。
- **H002、H007 的正期望不算候选证据**：两者都在黄金上，样本期包含 2019–2025 年的金价大牛市。对应机制的发表后证据也偏负面：
  - 波动率管理：Cederburg 等（2020），实时样本外表现一般不如原组合；
  - 时间序列动量：Huang 等（2020），逐资产几乎没有证据，与历史均值策略表现相近。
- **三张 v2 卡撤回**：H002-v2、H003-v2、H006-v2 是看过样本内结果后的迭代，H002-v2 的网格与预期笔数直接取自 v3 实测。处理规则：
  - 未运行过的：撤回，不计入试验次数；
  - 已运行过的：如实计入，并在候选登记表记录撤回原因。

### 6.2 选题流程：候选登记 → 预筛 → 轮次预注册 → 开卡

- **候选登记**：`research/candidates/C###.toml`（模板见附录 C），只写材料、不跑数据。
- **预筛硬条件**，全部满足才可进入轮次：
  1. 文献：原始论文 + 发表后或样本外的复现 + 已检索的反驳（写明检索词与日期）；预期效应按衰减折算（缺少复现时按发表后 −58% 估计，McLean & Pontiff 2016）；
  2. 持仓周期 ≥ H1；
  3. 事前成本：用成本模型 v3 估算，每笔预期毛利 ≥ 3 倍来回成本；
  4. 检验力：在现有数据长度上，按折算后的预期夏普，单次检验的检验力 ≥ 50%（附录 E），否则进"待数据"队列；
  5. 机制空缺：补组合里还没有的机制类别（趋势延续、反转、资金流与日历、风险溢价、波动率、跨资产、事件）；同类已有活跃谱系的，排在后面。
- **研究轮次预注册**：`research/rounds/R#.toml`（附录 D），提交且工作区干净后，该轮的第一次运行才允许开始。内容包括：
  - 本轮候选（最多 3 个新谱系）与每个候选的评估方式；
  - 试验预算（本轮最多多少次去重试验）；
  - 锁箱用量（本轮最多几次 G5）；
  - 推进规则：什么结果算过，过了之后不再在同轮挑选；
  - 结束条件。
- **迭代**：同一谱系的新版本也必须在轮次里登记并计入预算。"审查否决 → 直接开 v2"的旧路径取消。

### 6.3 瓶颈是数据长度与检验力，不是想法数量

按 Lo（2002）近似，单侧 5% 检验（脚本：`docs/reviews/probes/2026-10-27-round11-power.py`）：

| 真实夏普 | 研究段 | 单次检验的检验力 | 同轮 20 个试验时的检验力 |
| --- | --- | --- | --- |
| 1.0 | 4.3 年 | 52% | 13% |
| 1.0 | 6 年 | 64% | 21% |
| 1.0 | 10 年 | 83% | 41% |
| 1.0 | 20 年 | 98% | 80% |
| 0.5 | 6 年 | 31% | 5% |
| 0.5 | 20 年 | 68% | 24% |

按 T67 实测的 MT5 研究段：
- XAUUSD 11.77 年：夏普 1.0 单次检验力约 88%，夏普 0.5 约 49%；
- EURUSD、USTEC、BTCUSD 约 4.3–4.4 年：夏普 1.0 约 52–53%。

外部数据批准入库后，USTEC（FRED 日线约 40 年）、BTCUSD（Bitstamp 日线约 11 年）只对日线及以上的研究有效。

由此得出三条推论：
- 现有数据上，多测策略只会抬高门槛、增加靠运气过关的数量，真发现不会变多；
- 延长数据（外部数据，§6.5）比增加候选更有效；
- 1 年锁箱的标准误约 1.2，G5 只能拦住明显崩溃，确认还要靠前向样本。

### 6.4 低频策略的评估：事件模式

- **适用**：日历与资金流效应（每年约 12 次事件）、月度或周度再平衡类策略。
- **评估单位**：事件，不是成交笔数。主统计量为事件收益均值的单侧检验，按年做块自助；同一机制的多个品种可以合并。
- **样本量要求**：由检验力计算给出，取代 G1 的固定笔数。
- **标定**：用正负对照标定误报率与检出率——零假设为事件时间随机化（保持月内位置与星期分布），正对照为植入事件效应。标定完成并经用户批准之前，不开低频卡。

### 6.5 数据延长

- **目标**：
  - XAUUSD、EURUSD 拉长到 2005 年前后（含买卖价的外部报价源）；
  - USTEC 用纳指 100 指数日线（只用于日线及以上的事件类研究）；
  - BTC 从 2014 年起。
- **入库前核对**：
  - 价格口径（买价、卖价或中间价）；
  - 时区与夏令时（有的数据源用不随夏令时变化的美东时间）；
  - 与 MT5 重叠期的收益相关性与缺口；
  - 周末与换日结构；
  - 早年点差（有买卖价的按年估计，没有的用情景倍数）。
- **约束**：外部数据同样只用 cutoff 之前的部分；锁箱仍是 MT5 的 cutoff 之后段。使用前确认数据源条款。
- **现状（第十二轮）**：
  - 已批准：FRED 纳指 100 日线（指数 16:00 收盘口径）、Bitstamp BTC 日线；
  - HistData 待条款核实；它的时间标签实测按欧盟夏令时日历切换，早年文件要逐年验证；
  - 早年点差暂用情景倍数，直到有合规的买卖价来源（Dukascopy，或条款核实后的 HistData tick 文件）。

### 6.6 首批候选（只登记，不开卡）

- **C001 月末效应（USTEC）**：
  - 机制：月末与月初的固定资金流（工资、养老金、再平衡）；
  - 依据：McConnell & Xu（2008），1926–2005 年美股只在月末前后获得风险补偿，35 国中 31 国有此现象；
  - 待补：发表后证据；
  - 评估：事件模式，日线或 H1，每年约 12 次。
- **C002 月末对冲调仓（USTEC 当月涨跌 → EURUSD）**：
  - 机制：外国投资者为美股敞口做汇率对冲，月末按市值调仓，集中在伦敦 16:00 定盘前；
  - 依据：Melvin & Prins（2015）：当月股市上涨可预测该货币在月末定盘前贬值；
  - 待补：2015 年定盘规则修订后的证据，以及伦敦时间的夏令时处理；
  - 评估：事件模式。
- **趋势类（已有 H002 谱系）**：只有在补上"历史均值基准"对照（Huang 等 2020）并通过多品种合并的检验力测算后，才考虑登记。
