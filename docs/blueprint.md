## 1. 目标与范围

目标：agent 负责提出和检验假设、写代码、做监控；实盘只由通过验证关卡的确定性代码执行，
并受独立风控约束。

- 标的：XAUUSD、BTCUSD、EURUSD、USTEC（纳指 100，Exness 品名）
- 信号周期：M5、M15、H1（H4 可选）；M1 与 tick 用于执行、止损管理和 B 层回测
- 账户：Exness 模拟盘 → 小资金实盘（账户货币 USD）
- 暂不做：LLM 参与逐笔决策；M1 及以下剥头皮；机器学习黑箱模型

## 3. 架构（目标形态）

```
MT5 终端
 └─ mt5gw：与终端通信的唯一入口（行情 / 账户 / 交易；交易在同一次持锁内过保险丝）
     │
     ├─ 数据（管理员 / 实盘侧可读写）
     │    data/bars、data/ticks：全量，含锁箱期；每日定时刷新
     │    └─ export_research_store → data_research/：只含 cutoff 之前的 K 线 + 冻结的成本模型
     │
     ├─ 研究侧（研究 / 审查账户；CLI 缺省只读 data_research/）
     │    mt5quant：costs · sizing · strategies · backtest（A/B）· research（卡、台账）· validation（G0–G4）
     │    台账：每行带哈希链；试验身份 = 卡 + 参数 + 数据哈希 + 成本版本 + 策略代码指纹
     │    └─ 候选策略 ──（管理员批准）──► G5：一次性读主库锁箱段
     │
     └─ 实盘侧（每个策略一条同步链路 + 两个独立进程）
          运行器：向终端取已收盘 bar → 策略信号
            → 执行器：先写意图（expected-<magic>.json，目标持仓 + pending）
              → 风控闸门 check_open（同步；查 halt / killSwitch / pause / pause-<magic>）
              → 下单（只在开仓时定手数；持仓期间不调仓）→ 确认意图（confirmed）
            → 外部出场（服务器端 SL/TP）：按成交原因识别，意图改为空仓
            → 全平指令按编号消费：flatten.json{id} → flatten.ack-<magic>{id}
          风控进程：逐策略心跳、日亏上限、killSwitch → halt.json / flatten.json
          对账进程：意图 vs 实际持仓（pending 有宽限期）→ pause-<magic>.json；每日日报
          影子盘：同一条链路，下单改由影子券商按实时报价模拟成交（干跑与演练前的必经一步）
```

## 4. 铁律 v3.1

1. **时间**：
   - 库内时间是"贴 UTC 标签的 naive datetime"，实为经纪商服务器时间（Exness 为 GMT+0）；启动时用实测时钟校验 `server_utc_offset_hours`。
   - **随夏令时移动的事件一律用交易所本地时间定义**：换日 = 17:00 America/New_York（Exness 夏令时 21:00、冬令时 22:00 GMT+0），交易时段同理。禁止用固定 UTC 小时表示这类事件。
   - 配置里的本地时刻必须写明时区，并有长度上限校验。
2. **金额与手数**：
   - 价格单位与账户货币严格区分，`contract_size` 必填。
   - **定手数只有一个函数**（按风险比例与止损距离），回测、关卡、实盘共用，而且**只在开仓时调用**；持仓期间不因 ATR 或权益变化调仓。
   - 风控进程只设上限，不负责算手数。
3. **只用已收盘 bar**：信号在 bar i 收盘产生，bar i+1 开盘成交。
4. **Bid 基准**：K 线按 Bid；多头 Ask 入场、Bid 出场，空头相反；SL/TP 触发口径与 MT5 一致（多头按 Bid、空头按 Ask）；跳空穿过止损按开盘价成交。
5. **同一份策略代码，同一套执行语义**：
   - A 层、B 层与实盘对 SL/TP、跳空、reentry、time_stop、week_close 的处理一致；
   - 实盘不支持的出场规则在启动时拒绝；
   - 每个策略通过窗口不变性测试（≥100 个随机探针），实盘窗口取声明 lookback 的数倍。
6. **锁箱**：
   - 全部品种、全部周期共用一个固定 cutoff，只能更早不能更晚；
   - 研究侧 CLI 缺省只读研究库，研究账户在物理上读不到锁箱段；
   - 每张卡的 G5 只能用一次，整个锁箱另有使用预算（决策 D16）。
7. **可复现与试验计数**：
   - 每次运行写独占目录与 manifest，所有运行（含失败）进台账；
   - **试验身份包含策略代码指纹**，策略文件必须已提交且干净；
   - DSR 的试验次数按卡谱系去重计数，同时报告项目级总数；
   - 台账每行带哈希链，可校验。
8. **权限分离**：
   - 研究、审查角色只能新增卡文件、修改策略库与研究报告；引擎、关卡、成本、锁箱加载器、`bt`、风控与所有配置对其只读；
   - 执行点有三层：本地钩子（防手滑）、CI 侧路径白名单（防绕过）、ACL（防直接读写）。
9. **安全**：仓库公开——令牌、IP、账号、`config.json`、`mcp.json` 不得入库；MCP 只经隧道访问。
10. **实盘**：
    - LLM 不进交易环路；默认只允许模拟盘；下单路径同步经过风控闸门；
    - 任一停机信号（halt / killSwitch / pause）存在时禁止新开仓，平仓不受限；
    - 停机类文件读不出来时按"停机"处理。
11. **回测与实盘的禁入规则同源**：禁止开仓时段、点差闸门写在同一份配置里，引擎与风控共同读取。
12. **证据才算完成**：
    - 复选框只在附上证据（测试名、报告路径或日志）时勾选；
    - 证据分四级：单元、集成、真数据、真机；文档里声称的级别不得高于证据；
    - CI 为红时停止推送新功能，先修红。
13. **成本敏感性**：隔夜费率（历史利率不确定）与点差在 G2 做敏感性检查，结论不得依赖单一成本假设。成本模型写明样本覆盖（天数、季节、每小时样本数）。
14. **容差不因结果放宽**：对账、回归测试的容差只能依据机制设定（例如"B 层成交 = 边界后第一笔 tick"）；为了让结果合规而放宽容差，必须单独说明并经用户确认。
15. **跨进程文件契约**：
    - 所有跨进程文件用同一个原子写函数（临时文件 + fsync + 带重试的替换）；
    - 每个指令文件带编号，确认文件引用编号；
    - 每策略各写各的文件，避免多进程追加同一文件。

## 6. 研究方向（基于 gates-calibration-v2）

- **修正口径后的基线结果**：六张基线卡仍止步 G1，但失败模式从"全面崩溃"变成"单项临界"：
  - H002（唐奇安通道，XAUUSD H1）：PF 1.84，只差交易数（127 < 150）；
  - H007（波动率目标，XAUUSD H1，只做多）：PF 1.42，只差毛利/成本倍数（1.81 < 3.0）；
  - H003（纳指开盘区间，USTEC M5）：倍数 3.28 刚过线，只差 PF（1.084 < 1.2）。
- **先排除金价单边行情的影响**：H002、H007 都是黄金上的趋势/多头类策略，样本期包含 2019–2025 年的金价大牛市。下一步先过 G2 的"按年分段"与"买入持有基准"，区分收益来自策略还是来自金价本身。
- **低换手趋势类按多品种合并评估**：这类策略每个品种每年只有十几笔交易，G1 的交易数门槛按单品种几乎不可能达到。建议卡模板增加"合并评估"选项（交易数按全部品种合计，同时要求每个品种为正），由 T39 的对照实验确认这种评估方式的误报率后再启用。
- **H003 的结论依赖 USTEC 成本模型**：这个模型目前只有 12 天 tick。成本模型补强（T36）之后再判断，v2 卡沿用"H003-v2：after_signal_change"。
- **方向不变**：仍优先研究低换手周期（H1–H4、持仓数日）。

## 7. 模拟盘演练验收清单（阶段 F）

- 连续 10 个交易日，所有策略运行器、风控进程、对账进程不间断（重启有日志说明）；
- 无法解释的持仓差异 = 0；每笔成交可在台账或日志中找到对应决策；
- 服务器端止损、止盈出场后不触发暂停，同一策略按重入规则继续；
- 持仓期间零调仓（市价单数 = 入场数 + 出场数）；
- 演练全部通过：
  - 一键停机、心跳超时停机；
  - 日亏全平（**连续触发两次**，第二次同样全平）；
  - 对账不一致暂停（只暂停该策略）、断线重连、重复触发不重复下单；
  - 换日禁止时段（含冬令时 22:00）；
- 实际滑点与点差落在成本模型区间内（按小时比对，超出的小时写进报告）；
- 每日日报自动生成。
