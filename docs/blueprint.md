## 3. 架构（目标形态）

```
MT5 终端
 └─ mt5gw：与终端通信的唯一入口（行情 / 账户 / 交易；交易在同一次持锁内过保险丝）
     │
     ├─ 数据（管理员 / 实盘侧可读写）
     │    data/bars、data/ticks：全量，含锁箱期；每日定时刷新
     │    └─ export_research_store → data_research/：只含 cutoff 之前的 K 线 + 成本模型文件
     │
     ├─ 研究侧（研究 / 审查账户，只能读 data_research/）
     │    mt5quant：costs · sizing · strategies · backtest（A/B）· research（卡、台账）· validation（G0–G4）
     │    └─ 候选策略 ──（管理员批准）──► G5：一次性读全量库锁箱段
     │
     └─ 实盘侧（每个策略一条同步链路 + 两个独立进程）
          运行器：向终端取已收盘 bar → 策略信号 → 共享 sizing 定手数
            → 风控闸门 check_order（同步调用；先查 halt / killSwitch / pause）
            → 执行器：差分下单、止损随单、写 expected.json、消费 flatten 指令
          风控进程：逐策略心跳、日亏上限、killSwitch → halt.json / flatten.json
          对账进程：expected vs 实际持仓 → pause.json；每日日报
```

## 4. 铁律 v3

1. **时间**：库内时间是"贴 UTC 标签的 naive datetime"，实为经纪商服务器时间（Exness 为 GMT+0）；
   启动时用实测时钟校验 `server_utc_offset_hours`。**随夏令时移动的事件一律用交易所本地时间定义**：
   换日 = 17:00 America/New_York（Exness：夏令时 21:00、冬令时 22:00 GMT+0），交易时段同理。
   禁止用固定 UTC 小时表示这类事件。
2. **金额与手数**：价格单位与账户货币严格区分，`contract_size` 必填。**定手数只有一个函数**
   （按风险比例与止损距离），回测、关卡、实盘共用；风控进程只设上限，不负责算手数。
3. **只用已收盘 bar**：信号在 bar i 收盘产生，bar i+1 开盘成交。
4. **Bid 基准**：K 线按 Bid；多头 Ask 入场、Bid 出场，空头相反；SL/TP 触发口径与 MT5 一致
   （多头按 Bid、空头按 Ask）；跳空穿过止损按开盘价成交。
5. **同一份策略代码，同一套执行语义**：A 层、B 层与实盘对 SL/TP、跳空、reentry、time_stop、week_close
   的处理一致；实盘不支持的出场规则在启动时拒绝。每个策略通过窗口不变性测试（≥100 个随机探针），
   实盘窗口取声明 lookback 的数倍。
6. **锁箱**：全部品种、全部周期共用一个固定 cutoff，只能更早不能更晚。研究账户在物理上读不到锁箱段
   （只读研究库）。每张卡的 G5 只能用一次；整个锁箱另有使用预算（决策 D16）。
7. **可复现与试验计数**：每次运行写独占目录与 manifest；所有运行（含失败）进台账；
   DSR 的试验次数按卡**谱系**去重计数，同时报告项目级总数。
8. **权限分离**：研究、审查角色只能新增卡文件、修改策略库与研究报告（白名单钩子 + ACL）；
   引擎、关卡、成本、锁箱加载器、`bt`、风控与所有配置对其只读。
9. **安全**：仓库公开——令牌、IP、账号、`config.json`、`mcp.json` 不得入库；MCP 只经隧道访问。
10. **实盘**：LLM 不进交易环路；默认只允许模拟盘；下单路径同步经过风控闸门；
    任一停机信号（halt / killSwitch / pause）存在时禁止新开仓，平仓不受限。
11. **回测与实盘的禁入规则同源**：禁止开仓时段、点差闸门写在同一份配置里，引擎与风控共同读取。
12. **证据才算完成**：复选框只在附上证据（测试名、报告路径或日志）时勾选。"完成"分三级：
    单元、真数据、端到端；文档里声称的级别不得高于证据。
13. **成本敏感性**：隔夜费率（历史利率不确定）与点差在 G2 做敏感性检查，结论不得依赖单一成本假设。

## 6. 研究方向（基于 P5 证据）

- 六张基线卡全部止步 G1，主要原因是成本：日内 M5 突破类策略在"目标仓位 + 止损后立即重入"的语义下，
  换手是卡上预期的数倍（H003 预期 200–250 笔/年，实测 4,006 笔 / 约 4.3 年，约 900 笔/年）。
- 测量修正后先重跑基线，再开 v2 卡：H002-v2（只做 BTCUSD）；H003-v2（`reentry="after_signal_change"`）；
  H006-v2（提前 15 分钟离场，避开维护窗）。三张都是原卡谱系的新版本，计入原谱系的 N。
- 优先研究低换手的周期（H1–H4、持仓数日）：研究范围报告中 H1 的成本与波幅之比约 0.4%–3%，
  远低于 M5，成本门槛容易通过。

## 7. 模拟盘演练验收清单（阶段 F）

- 连续 10 个交易日，所有策略运行器、风控进程、对账进程不间断（重启有日志说明）；
- 无法解释的持仓差异 = 0；每笔成交可在台账或日志中找到对应决策；
- 演练全部通过：一键停机、心跳超时停机、日亏全平、对账不一致暂停、断线重连、
  重复触发不重复下单、换日禁止时段（含冬令时 22:00）；
- 实际滑点与点差落在成本模型区间内（按小时比对，超出的小时写进报告）；
- 每日日报自动生成。
