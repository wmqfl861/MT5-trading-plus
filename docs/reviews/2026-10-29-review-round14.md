## 2. 关卡 v3 冻结：批准与条件

**依据**：
- 预写规则逐条执行；
- 甲在 18 个误报格上都是 0%（每个 N 合计 0/120，95% 置信上界约 2.5%）；
- 甲在 N=6 时，夏普 1.0 的联合检出率为 H1 65%、H4 100%、MERGED 30%。
- 丙的检出率更高，但在 N=2 有一格误报 15%。单格 20 个种子的统计力度有限，这条规则偏严、偏吵，但它写在结果之前，不能事后改。
- 结合下面的 L2，低 N 时 PSR 家族的误报确实偏高，选甲更稳妥。

**冻结提交的四项条件**（同一提交完成，并配失败测试）：
1. **L1：配置与分派指向方案甲与新的 N 口径**
   - `[v3] primary_test = "dsr_v0"`，`V3_PRIMARY_TESTS` 加入该值，`run_primary_test` 分派到 `v3_primary_dsr_null_variance`；
   - `[g4] dsr_trial_scope = "rounds_lineage"`，含义是 N = `ledger.primary_test_n(continues_family)` 的门槛部分；
   - 台账经验方差只进诊断；
   - 失败测试：按冻结后的配置走 `run_primary_test`，结果必须与 `v3_primary_dsr_null_variance` 逐位相同，且 N 取自 `primary_test_n`。
2. **L2：N 下限取 2**
   - `[v3] n_min = 2`，主检验用 N_eff = max(N, n_min)；
   - 事件模式分支不受影响（随机化检验在 N=1 时也是精确的）。
3. **T65 报告加注**：在 `gates-v3-proposal-2026-10-28.md` 开头注明，其数字按 T83 之前的成本口径计算，已被 T85 取代。
4. **提案 §8 的其余步骤**：`gates.toml` 替换、冻结指纹更新、蓝图附录 B 与 D34 记录同步。

**工作范围的提醒**：
- 甲的检出率随 N 下降很快：H1 夏普 1.0 在 N=24 时只剩 40%。
- H 线每轮的试验预算要小，低频机制优先走事件模式，或先延长数据。

## 3. 发现

### High

**L1 冻结前的配置不会执行选中的方案**
- `gates-v3.toml` 仍是 `primary_test = "dsr"`、`dsr_trial_scope = "project"`。
- `run_primary_test` 对 "dsr" 分派的是 `v3_primary_dsr`，它使用调用方传入的台账试验夏普，也就是经验方差。
- bt 按 "project" 取数，得到的 N 计入了全部历史研究运行。
- 也就是说，照现在的文件冻结，生产路径跑的仍是第十三轮 K1 指出的旧口径，而不是 T85 选中的甲（V₀，轮次加延续谱系）。
- 处理：冻结条件 1。

**L2 N=1 不在标定范围内，而这一点的 PSR 误报偏高**
- T85 §4.3：按修正后的成本口径重跑，N=1 时 `joint.dsr` 在 H4|slot 上误报 25%，单检 30%。
- 5/20 相对名义 5%，单侧 p 约 0.003，不是噪声。
- 标定网格只覆盖 N ∈ {2, 6, 24}。H 线第一轮如果只有一个 bar 级试验、又不延续谱系，N 就是 1，正好落在未标定、误报偏高的那一点。
- 处理：冻结条件 2（N 下限 2）。误报偏高的来源另做诊断（T95，不阻塞冻结）：零假设是否保留了样本漂移、持仓期内权益收益是否自相关、买入持有否决在置换序列上的行为。

### Medium

**L3 研究年数把内部空洞算进去了，C002 的"通过"不成立**
- `coverage_segments` 对每个序列只取首尾时间作为一段。HistData EURUSD 2013→2022 中缺 2014、2019 两整年，仍按 9.99 年计入；与 MT5 段并集后得到 12.81 年。
- 按这个年数，C002 的检验力是 50.5%，刚过 50%。T87 报告自己也写了：按实际数据密度约 10.8 年，检验力约 45%。
- 处理（T94）：
  - 分段在长于 30 天的内部空洞处切开（同时读 manifest 里未启用的年份与 `known_gaps`），再求并集；
  - C002 改回 waiting_data；
  - 补下载 EURUSD 2003–2012 年与 2025 年（截至 cutoff），逐年过闸后重检。

**L4 定盘锚点"判不出"不应排除年份**
- 2014 年的标签规则检测很干净（偏差 0 对 33），只因定盘锚点余量 1.10 恰好在门槛上，判为 undetermined，就被排除了。
- 锚点用的是月末定盘窗口的波动强度，而这个强度与 C002 的机制（月末对冲流）相关。按"尖峰够不够强"取舍年份，等于按效应强弱挑样本。
- 改为：
  - 锚点判为 inconsistent（尖峰出现在错的小时）才排除；
  - 判为 undetermined 时，以标签规则检测为准，并在 manifest 里注明。
- 处理：T94（2014 年重新判定入库）。
- 另，这类校验只用与方向无关的结构量（波动、成交密度），不计算与假设方向相关的统计量。T87 目前的做法符合这一点。

**L5 订单注释：根因更可能是长度，上限 31 仍然偏高**
- 事故注释 `XAUUSD|M15|2026-10-28T06:30:00` 正好 30 个字符。
- 两份公开报告实测：MetaTrader5 Python 库对 30 个字符及以上的注释返回 `(-2, 'Invalid "comment" argument')`，29 个字符可以通过；没有提到 `|` 或 `:`。
- 现在的修复因为把注释压缩到了 20 个字符，碰巧能用；但 `MT5_COMMENT_MAX = 31` 让 30–31 个字符的注释仍会被拒。
- 处理（T89，放在下一次计划内停机时做，不必紧急停机——目前所有下单路径的注释都 ≤ 20 个字符）：
  - 上限改为 25；
  - 在模拟盘上用 `order_check`（不下单）各测一次 29、30 个字符的纯字母数字注释，以及含 `|` 的短注释，把实测结果写进代码注释与测试；
  - 区分"客户端参数错误"（last_error 为 −2，请求根本没发出去，状态是确定的）与 IPC 中断（状态未知）：前者直接报错并告警，不走"核对持仓再决定"的流程。

**L6 阶段 F 的事故与重启没有记录**
- 仓库里只有修复提交，看不到以下信息：阶段 F 何时启动、首笔订单被拒的时间与影响、何时停机、何时恢复、10 个交易日从哪天起算。
- 蓝图 §7 允许"重启有日志说明"，前提是有这份说明。
- 处理（T89，立即做）：新建 `docs/ops/phase-f-log.md`，逐日记录启动、事故、停修、恢复与当日演练项。不写账号、服务器名、IP。

**L7 推送前验证失效，多代理共用一个工作区**
- **语法错误被推送**：f46fd9e 把注释插进了 `reconcile_ab.py` 与 `reconcile_mt5_tester.py` 的赋值语句中间，两个脚本都有语法错误。CI 变红约一小时，期间另一次推送也被连带变红。4228926 的说明承认，本地回归的退出码被管道吞掉了。
- **提交互相卷入**：T83、T84、T88 由几个代理在同一个工作区并行完成，提交互相卷入——T84 的内容分散在 T83、T88 的提交里，T83 自己的 bt.py 接线漏在 T84 的提交里。中间提交各自并不自洽。
- **证据引用的提交号不存在**：复选框证据引用了 `8259aa4`、`598a5c1`、`330e826`，它们是变基前的本地提交号，在 main 上不存在；main 上实际对应的是 5d39dbe、52e3335、bcdb204。
- 处理（T96）：
  - 并行代理各用一个 `git worktree`，或者改为顺序执行；
  - 回归命令显式检查退出码（`set -o pipefail`，或单独保存 RC 后再判断）；
  - 每个提交在自己的树上全量回归通过后再推送；
  - 证据行只引用 main 上的提交号与 CI 运行号；修正上述三处引用。

### Low

- **L8 隔夜费参考价**：参考价取研究库最后收盘（cutoff 时点），但快照里的隔夜费点数是按快照时点的价格定的。两者差几个百分点。建议快照时同时记下买卖价，用它作参考价（T96，可选）。
