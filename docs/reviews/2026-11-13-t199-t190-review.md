## 2. 重点 2：T190 meta_path 兜底 finder（tests/conftest.py）—— 通过

### (a) 末位挂载的惰性 —— 证实

`sys.meta_path.append`（幂等检查后）挂末位。装齐包时：PathFinder 在前、解析成功即终止 meta_path 遍历，兜底 finder 不会被问及；实测确认它位于 meta_path 末位，且对非清单根名（如 `json`）返回 None、不抛。`tests/test_optional_dep_skip.py::test_all_optional_deps_installed_and_finder_inert` 有显式惰性断言，本机复跑通过。`OPTIONAL_HEAVY_DEPS`（MetaTrader5/pyarrow/duckdb/mcp）与 src 顶层 import 逐一对齐（`src/mt5data/ticks.py` 顶层 `pyarrow.parquet`、`src/mt5mcp/tools.py` 顶层 duckdb、`src/mt5mcp/server.py` 顶层 mcp、MetaTrader5 延迟导入），子模块按根名命中（`find_spec` 取 `fullname.split(".",1)[0]`）。

### (b) pandas 探测点的栈帧识别 —— 当前版本正确；升级脆弱性记 Low-2

识别逻辑写死栈帧 `__name__ == "pandas.compat.pyarrow"`。动态实验（屏蔽 pyarrow 模拟缺席 + 加载 conftest + 清 sys.modules）：

- `import pandas` **成功**，`pandas.compat.pyarrow.PYARROW_INSTALLED = False`——探测点拿到普通 `ModuleNotFoundError` 正常降级，**零连坐**。该实验同时证明当前 pandas 3.0.6 的 `import pandas` 顶层链上**确无第二个**"吞 ImportError 降级"的 pyarrow 探测点（若有，BaseException 派生的 Skipped 会击穿 `except ImportError`，import pandas 当场失败）。静态 grep 亦支持：pandas 包内裸 `import pyarrow` 语句虽多，但其余全在函数体内（延迟）或 TYPE_CHECKING 块下。
- 本机 pandas 3.0.6 的 `pandas/compat/__init__.py` 顶层 `from pandas.compat.pyarrow import ...`，与 conftest 注释的探测链描述吻合。

脆弱性评估（Low-2）：若未来 pandas 大版本把该探测模块改名/搬家，缺包机器上 `import pandas` 会收到 Skipped 并连坐跳过所有 pandas 测试——症状是**静默 skip 扩大而非红**。缓解因素：`requirements.txt` 钉死 `pandas==3.0.6`，升级必是显式动作；装齐依赖的机器（CI）完全不受影响。结论：可接受，升级 pandas 时需重跑缺包模拟验证。

### (c) Skipped 透传只在 pytest 会话内 —— 边界确认

`tests/conftest.py` 仅在 pytest 收集 `tests/` 时被自动加载：仓库**无根级 conftest.py**；`src/`、`scripts/` 下无任何 `import tests.conftest` / `import tests` 引用。生产进程（live_runner、risk_process 等独立 python 进程）的 `sys.meta_path` 里没有这个 finder，缺包时得到的是正常 ModuleNotFoundError——Skipped 透传路径在原理上不可能在生产代码触发。运行期透传行为实测：`df.to_parquet(...)` 与 `pandas.io.parquet.get_engine("auto")` 均收到穿透 pandas 栈帧的 `_OptionalDependencySkipped`（pandas 的 `except ImportError` 接不住 BaseException 派生类，符合设计），收集期直接 `import pyarrow` 抛 `_OptionalDependencySkipped`（isinstance Skipped、`allow_module_level=True`）。
