## 3. 实现者自述 5 处偏离裁定

| 偏离 | 裁定 | 理由 |
| --- | --- | --- |
| 1. 多候选轮 v1 只彩排首候选 | **可接受** | round open/screen/gate/verify 对每个候选是同一条命令链，机械同构；报告明示口径（candidates_all 全列 + "v1 只彩排首候选口径"）。残余缺口：候选 mode 混合（如首候选 event、次候选 bar）时其余 mode 的命令形状未彩排——见 F-5 建议，不阻塞 v1。 |
| 2. 概率轮只彩排开轮段（screen/gate skip） | **可接受** | D69 P 线休眠（不运行 T121 v2、代码冻结），fit/prob test 链本就不该跑；skip 理由（含 D69 引用）如实写入 stage 与报告，测试断言 stage_status=skipped；开轮段本身含 D52 假设族冻结机械路径（影子 rounds 行 `__frozen_hypotheses__` 测试断言）。重启 P 线时须扩展本命令（skip 文字已自指）。 |
| 3. 合成候选登记（替代真实候选 toml） | **可接受** | D67 要求安慰剂输入——候选登记的数据源（文献/σ/检验力）属真实输入，必须替换；合成物保留与预注册交叉核对的关键字段（side_rule 逐字一致、probability 的 situations/hypotheses 取自轮次预注册），使 `round open` 的 T112 交叉核对与 D52 复核走**真实代码路径**而非旁路；合成候选 title/mechanism 自明"彩排安慰剂（合成）"。 |
| 4. 预筛 pass 作夹具种子（直写影子 candidate_checks） | **可接受** | round open 前置核对要求候选有 pass 预筛，真实预筛结论属真实输入不可复用；夹具写**影子**台账（note="T153/D67 rehearsal placebo fixture" 可辨识），概率候选另带 per_hypothesis 触发日数使 D52 复核机械可走。正式台账零接触（§2）。夹具未带 candidate_sha256 使 H-08 内容绑定核对走了兼容路径——覆盖缺口记 F-3。 |
| 5. 提交后复跑前提（事件链需干净判决树） | **可接受** | T188/D75 的 verdict_code_sha 干净树检查是既有机器约束（保护判决指纹完整性），非本提交新增限制；测试 docstring 显式声明前提。"实现者改完代码未提交就彩排 → gate 阶段 fail-closed 拒绝"正是想要的机械暴露，不是缺陷。 |

## 4. 红旗检查

1. **彩排会不会被误当成真结果**——不会（多重醒目）：md 标题"彩排报告 R#（T153/D67，开轮前）"与文件名 rehearse-R#-*；卡 id=H901 独立号段、候选/卡文件 title/phenomenon 自明"彩排安慰剂（合成）"；关卡表上方固定免责文字"安慰剂上只报告、不进彩排判定——无效应下关卡不过属预期"；gate rc=1 在报告显示"✓（机械完整；关卡实质结果见下表）"；影子 runs 行 actor 全带 `bt-rehearse-` 前缀（测试断言，事后审计可拣出）；verdict 只判机械完整、不判实质通过。残余（Minor 不阻塞）：安慰剂上关卡碰巧全过时，报告未显式加"属种子运气、非证据"标注，靠表头免责文字覆盖。
2. **沙盒清理是否完整**——完整。沙盒自包含于 `data/rehearse/<R#>-<UTC时刻>/`（repo/store/ledger.sqlite/rehearsal-report.json），`data/` 在 .gitignore（不入库）；迷你 git 仓库与影子台账全部在目录内，删除该目录即彻底清理、无外部残留；md 报告写明该目录路径与"事后删除即清理"。无自动清理子命令（F-4，Low：多次彩排会积累目录）。
3. **sha256 绑定是否真防替换**——真防。`--fomc-calendar-sha256` 不是仅记录：validation/events.py:254–266 对日历工件**文件字节**计算 sha256 并与期望值比对，不符即 ValueError fail-closed（"不得静默换用重抓日历"），且 --event-kind fomc_calendar 时四参数成对强制；另有 F1 机械核对（有登记载荷时 CLI sha 须等于台账登记 sha）、round toml sha256 入报告（人审可比对）、gates.toml 冻结 sha256 由 load_gates 强制。彩排自身把安慰剂日历 sha（rehearse 计算）传 CLI 走同一校验——替换安慰剂文件会被机器拒绝。

## 5. 问题分级

- **F-1 [Low]** `formal_round_status`（rehearse.py:189–204）对所有 `sqlite3.Error` 一律返回 None（视为未开启，fail-open），与 `formal_chain_heads` 的 fail-closed 不一致。兜底成立：同一库若锁定/损坏，随后 `formal_chain_heads`（heads_before，:529）同样失败 → RehearseError 中止彩排；但此时沙盒+夹具已建（残留一个无报告的沙盒目录）。建议 catch 收窄到"表不存在"类错误，与注释意图一致。
- **F-2 [Low]** 报告 red_lines 键 `no_approved_by` 措辞"不写任何 approved_by/lockbox 行"与事实有字面出入：影子台账 rounds 行含 approved_by 字段（继承预注册必填字段、随真实 round open 代码路径写入影子库）。实质红线（不伪造批准、不写正式台账、不触 G5）全部成立；建议措辞精确为"不写正式台账任何行、不产生任何批准动作；影子 rounds 行继承预注册 approved_by 字段（沙盒内）"。
- **F-3 [Low]** 两段开轮机械核对未进彩排覆盖面：① 夹具 candidate_checks 行不带 `candidate_sha256` → H-08"候选内容与预筛结论一致"核对走"旧记录未绑定"兼容路径；② 影子台账无 precheck 载荷 → F1 日历登记交叉核对标注 no_registered_precheck 不比对。均不产生错误结论（fail-closed 方向），但彩排对开轮核对的覆盖打了折扣；建议夹具补齐两载荷，或在本模块 docstring 声明覆盖边界。
- **F-4 [Low]** 沙盒无自动清理/清理子命令，多次彩排在 `data/rehearse/` 逐次积累目录（每份含迷你 git 仓库+parquet+影子台账，量级小）。建议后续加 `--cleanup` 或在 CLI 输出里列出清理命令。
- **F-5 [Low]** "同一条命令"的两处口径差异建议文档化：① screen/gate 带 `--allow-unbounded-data`（合成库无 lockbox 语义，豁免必要，但真实运行不带此 flag，X-03 裸库拒绝一类故障不在彩排暴露面内）；② 多候选混合 mode 轮次只彩排首候选 mode 的命令形状（偏离 1 残余）。argv 全量落报告可审计，暂可接受。
