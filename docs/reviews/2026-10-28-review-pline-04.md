## 必改（T92 之前；现在没有别的阻塞，建议现在改）

### E1 P2 决策卡在 screen、gate 里跑不起来（T73A）

- screen 与 gate 都先把数据切到 [split, cutoff)，再调用 `_prob_fit_context` 拟合。拟合取的是 < split 的部分，这时已经是空的，于是一律报错"在分界之前没有数据"。
- 新增测试只单独测了切片函数，没有测 validation 卡走完 screen 或 gate。
- 实验 R7（复现脚本 04）：临时仓库、跨分界的合成数据、已开启的轮次，standard + validation 的决策卡跑 `bt screen` → 退出码 1。在审核环境里把切片挪到拟合之后、并放行 E2 的五个字段，同一张卡退出码 0、台账一行成功运行，拟合窗止于分界。
- 评估窗也没有预热：从分界那一根开始回测，ATR、SMA200 与 2,000 根的 ATR 分位都没有历史，验证段开头约四个月的特征是空值。
- 改：
  - 先拟合（训练窗 < split），再切评估窗；
  - 评估数据从分界往前多取 `required_data.lookback_bars` 根作预热，分界之前信号为 0，指标只按分界之后入场的交易计算；
  - 补端到端测试：validation 决策卡经 screen、gate 跑通，所有交易都在分界之后入场。

### E2 蓝图附录 A 的决策字段写不进卡（T73A）

- 附录 A 的 `[prob]` 有 `features`、`prior_strength`、`min_cell`、`lb_z`、`entry_threshold_cost_mult`。`[prob]` 的校验只认八个字段，这五个一写就报"未知字段"。
- 卡与策略类常量的核对也没有覆盖这五项；`prior_strength`、`min_cell` 在 `fit` 里写死为 100。
- 实验 R7 的前半：按附录 A 写完整 `[prob]` 的卡，现在装载就失败。
- 改：
  - `[prob]` 接受这五个字段，校验类型与取值；
  - 核对覆盖这五项；`prior_strength`、`min_cell` 改为策略类常量；
  - 实验 R7 的后半：`lb_z` 与策略类不一致的卡必须被拒。
- 附带：standard P 卡的 `primary_statistic` 现在只接受 `max_net_profit`，那是选参规则，不是主检验。T73B 时按冻结后的关卡 v3 主检验改；蓝图附录 A 已写明 D34 冻结前不能用于正式运行。

## 小改

### E3 方向冲突（T74）

- 现行：只在"同一动作、方向相反、期望值相等"时放弃，其余情况取期望值最高的方向。
- 决定（蓝图 §2.5 第 4 条与 D41 已补充）：同一根 bar 上方向相反的动作都过门槛时不做。两个方向的估计各自没有考虑对方，信号冲突时按缺省不做。
- 单局面的卡上这种情况本来就少，影响主要在 P2 的多局面决策卡。

### E4 缺值时按宽松处理（T74）

- `generate_signals` 查不到成本时按 0 计，门槛形同虚设；改为不参与决策。
- `fit` 缺入场政策时按"不限制"处理；改为报错。
- `LevelDecisionS1Demo` 的常量被改成了探针卡的取值（K = 8、网格 2.0）。作为演示类可以接受，文档字符串注明只供测试与探针，真实卡各自定义子类。

### E5 误报率单元测试太弱（T75）

- 计划写的是 1,000 次重复；现在是 40 次重复、每次 50 次置换。50 次置换时 p < 0.05 要求 k ≤ 1，名义水平变成约 3.9%；40 次重复的估计误差约 ±3 个百分点。
- 改：至少 400 次重复、每次 ≥ 200 次置换；太慢就标成慢测试，CI 外单独跑，复选框写日志路径。正式误报率以 T75 标定为准。

### E6 round-report 与 P1 入口（T90）

- 成本读的是磁盘上的预筛 JSON，开轮后重跑预筛就会变；改为读开轮时已入账的那一行（台账 `candidate_checks` 中开轮时刻之前最新的一行）。
- `cost_r_by_symbol` 为空时按成本 0 处理；改为拒绝。
- 提交说明写的是按候选过滤运行，代码实际按"卡号以 P 开头"过滤。改为 `bt prob test` 把候选号写进 `params_json.prob`，报告按（候选, 假设）过滤。
- `run_p1_card` 的入场政策缺省为 None（等于不限制）；改为必填。
