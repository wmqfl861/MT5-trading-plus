## 1. 裁定量 (a)：R3 轮次处置

**裁定：其他——"附条件双路径终局"，既非 advance 亦非 close-not-
advanced。**逐项论证：

- **备选 (i) 纯台账事实**："无 V3 行 → 机械上无法 advance"——
  **采纳其前半**（机器判定载体缺位，任何 advance 动作无判定对象）；
  **否决其后半**（由"无行"推出"诚实未过"）。"未通过"在预注册语义
  下需要主检验 p>α/N 或否决项失败或（若诊断可否决——它不能）诊断
  失败的**真实判定记录**；本案三个判定项全部过门，"未通过"无证据
  载体。台账缺位只能推出"无机器判定"，推不出"未过"。
- **备选 (ii) 台账 run#451 + G0 行 + 离线确定性复现组合**：作为
  **证据**成立（本裁定 §0.5 已独立复算至逐位一致），作为**判定
  载体**不成立。理由：advance_rule 的判定依据="本文件与冻结
  gates.toml 的预写规则"，其机器执行者是引擎关卡；由 A1 裁定宣布
  "复现结果即视同 V3 passed=1"将开创裁定者改判关卡结果的先例，
  破坏 append-only 台账权威性与"判定不按结果临时调整"的结构保障。
  本裁定据 (ii) 认定的是**事实**（判定项全部过门、缺陷确定性），
  不是**动作**（advance）。
- **本裁定采纳的基础 (iii)**：R3.toml advance_rule 预写文本（逐字）
  + 其判定项的确定性证据（离线复现+裁定者独立重算）+ 台账 V3 行
  缺位事实 + 引擎缺陷定性（§2）四者组合。该基础推出的唯一结论：
  **C005 的机器判定被引擎缺陷阻断，而非被预注册规则否决**；因此
  处置必须先解决"判定载体"问题（修复后让引擎产出真实 V3 行），
  或诚实登记"判定缺位"后关闭。
- **为什么不能选 close-not-advanced 字面形态**：close_rule (b) 的
  "未通过者登记结论关闭"预设"未通过"是预注册规则的产物。本案若
  登记"未通过"，其唯一支撑是反事实错误行——那是缺陷行为，不是
  规则行为。把缺陷行为登记为研究结论，等于向谱系注入一条假阴性
  （主检验 p=0.0085 过门却记"未通过"），对 D33 N 计数与后续候选
  （同族 N2）的先验构成系统性污染。这与登记"无有效机器判定"
  （路径 B）有本质区别：后者如实、不产生假阴性。
- **为什么不能选 advance 字面形态**：无台账 V3 行（机械阻断）；
  且即便认为复现证据足够强，advance 还需 G5/锁箱程序（close_rule
  (b)：通过者最多 1 次 G5 后关闭、锁箱使用需另经批准）——该程序
  的入口同样是有真实的 V3 通过行。跳过程序的 advance 是越权。

## 2. 裁定量 (b)：诊断异常的语义定性

**裁定：实现缺陷（"report-only 诊断被升级为关卡失败"），不是设计内
fail-closed。**缺陷登记建议编号（沿项目 F 系列）：由主会话按台账/
文档惯例分配，本裁定以 **ENGINE-DEFECT：v3_event_diagnostics
window_shift 段异常升级** 指称。五重证据：

1. **冻结规范三处一致排除**：gates.toml [v3.event].diagnostics 数组
   注释"D35 修改 3：诊断四项（**只报告，不否决**）"且 window_shift_1_bar
   明列其中；R3.toml advance_rule"诊断四项……只报告不否决"；R1.toml
   先例同句。若设计意图是诊断异常中止关卡，三处不会同时把诊断层
   排除在否决机制外。
2. **函数自身 docstring 明文覆盖异常情形**："passed 恒 True（报告层
   语义：**诊断失败不改变关卡结论**）"——"诊断失败"自然语义含
   "诊断计算异常"，设计意图是它不改变关卡结论。
3. **同函数不对称保护 = 疏漏的直接内证**：year_block_vs_zero 段
   try/except ValueError → {"passed": True, "reason": …}，证明
   "诊断异常降级记录"是该函数已实现的设计意图；window_shift 段
   漏掉同等保护不是设计而是遗漏。且该段输出结构含 "dropped" 字段
   （非 strict 路径的计数语义），设计预期平移后不可解析事件被计数
   报告而非致命。
4. **strict_windows 的语义域越界**：其 fail-closed 的动机注释明文
   是"随机化 null 样本中缺失观测不能静默消失"——合法域=主检验
   随机化抽样与装配段原始观测事件（可成交性）；诊断平移副本既非
   null 样本也非主检验观测。主检验 1999 抽取与 213 观测事件在
   strict 路径下全部成功完成（p=0.0085 可复算）——fail-closed 在
   其合法域内从未触发；唯一触发点恰在语义域外的诊断段。
5. **数据形状必然性（非偶发）**：假日邻接事件的 +1 平移恒无 bar
   （裁定者独立证实 1996-07-04 无 bar；fomc_calendar 213 事件中
   1996-07-03 事件必撞独立日假日）——这不是可回避的边角，是该
   事件族的结构性形状。R1 london_fix 先例（V3 rowid 77 完整落账）
   只说明 london_fix 形状未触发，不能证明设计容纳本形状。

**定性边界（防止过度推论）**：本裁定不认定 strict_windows 本身缺陷
（其主检验域行为正确且必要）；不认定 SignalUnavailable 机制缺陷
（其防静默丢观测语义正确）；缺陷**恰一处**：诊断层 window_shift 段
将主检验域的 fail-closed 异常未捕获地传播为整关卡失败，违反诊断层
"只报告不否决"的冻结语义。
