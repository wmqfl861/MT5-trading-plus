## 2. R1 发现与闭合

首轮发现：真实 `candidate check` 只收集成交 `symbols × holding` 的覆盖，H预筛又过滤掉辅助输入；运行装载器却依赖这些记录选择merged，并在信号独立基线缺失时借用总体年数。已有夹具手工写辅助覆盖，没有证明真实前置链路。

修订后的独立复核确认：

| 环节 | 结论与证据（d7e0a00行号） |
| --- | --- |
| 精确输入集合 | `candidates.py:1077 required_input_pairs` 收集交易输入及辅助信号输入，支持跨品种、同品种不同周期、仅声明signal_timeframe；去重后没有多余的品种×周期组合。 |
| 真实候选预筛 | `scripts/bt.py:2153` 按精确输入对收集覆盖，辅助缺失记录为空覆盖；H预筛保留逐输入年数和来源，并按所需输入最短年数计算检验力。 |
| 成交与信号范围 | 成本、swap参考价、事前成本及交易波动循环仍限成交品种；不为取得信号覆盖把USTEC加入成交品种，也不要求其交易合约。 |

## 3. 原模块已审范围及证据边界

首轮完整审查检查了逐事件方向、跨品种B7、真实merge输入、G0、成本与身份接线；发现R1后不以其他局部正确性抵消该阻塞。R1修复后，审核者结合首轮结果形成最终模块结论。

- 观测与随机事件共用方向回调。窗口采用上月与本月倒数第二交易日明确收盘，必须严格早于入场；缺锚为不可用，平盘是零敞口。冻结sampler未改，不换种子、不补抽样池。
- B7研究绑定要求USTEC/mtd_sign，拒绝隐式同序列代理。G0同步裁剪辅助价格、强制覆盖计划事件点，并使用有界40天预热；计划交易日历与未来价格分别处理。
- FRED D1使用明确日期收盘映射；MT5 D1要求自身显式bar_time/close_time映射，不猜24小时或借用FRED收盘。
- 引擎改动只在既有spread调用点选择来源成本上下文，包括空头Ask止损/止盈和mark；没有改成交公式、分支、时序或SL/TP优先级。合成对拍比较旧引擎与新legacy/MT5输入，多空、固定/风险手数、非零swap和overshoot输出逐位一致。
- 外部来源只放大点差×1.5；V3全成本压力独立。覆盖、来源、坏月、缺口和可用事件写入台账与可见报告。
- 复合输入身份覆盖信号内容、来源、日历和规则版本，进入reservation、成功运行去重、自动选参及G3/G5证据匹配；P v2与历史记录保持兼容。

现有测试结果来自实现者日志，主会话已读取；审核者未重复运行套件：首轮相关537项通过，最后T112/B7专项51项通过；R1定向178项通过、退出码0（审核者亦直接读取）；H15-1/2为NOT-REPRODUCED，受保护探针不变。原七项源码漂移失败保留，不能算最终绿灯。编辑期间运行的旧全量不计最终版本验证。
