## P 准入适配器

独立结论：**approved，仅批准所提出接口设计、离线实现及纯合成正负路径测试；不批准任何真实 release、来源、材料、读取或计数。**

1. 生产信任根固定于受审代码版本，初始注册表为空，仅映射 `release_id → 审核清单原始字节 SHA256`。调用者 JSON、CLI 或环境变量不能替换注册表或提供信任根。哈希只证明身份；未来真实条目须来自有授权、独立于实现者的审核记录，由主会话注明来源转录，开发者不得填批准。
2. 清单须绑定版本、release_id、独立审核记录身份及哈希；数据、源 manifest、六个成本组件、代码和冻结规则的版本及字节哈希；用途、品种/周期/账户/时间范围、依赖、有效期、条件闭合证据及唯一执行标识。缺项、未知或冲突均拒绝。
3. 读取 data/cost 之前先查固定注册表，核验清单哈希及执行范围/状态；未知 release 当场拒绝。获准后逐工件读取并核对字节身份，解析同批已核验字节，再调用既有计数成本内核，不重开路径取另一批内容，不通过改 synthetic 标签授权。原纯元数据接口仍保持 `not_released`。
4. 每次按协调方确认的当前注册表、撤回快照及可信时刻验证；未知、过期、撤回或条件未闭合拒绝。读取数据前原子占用一次执行标识；失败也不自动重用。消费记录须跨进程、重启及 worktree 保留，旧快照不能恢复权限。重跑需新独立放行，材料或范围变化须重审。
5. 隔离测试注册表可使合成工件完整经过核验、同批解析和原内核；覆盖篡改、错绑、未知/撤回/过期、重复消费、自填批准拒绝。生产入口不能提供测试替换开关。实现完成仍须 D62 独立审核，不建立签名服务或通用权限平台。

### 实施中独立复核的设计修订

首轮实现审核发现撤回观察水位未持久化、登记与实现身份循环绑定。原独立审核者给出六条 conditional 修订条件，以下由主会话转录；条件只是离线修复的设计依据，实现仍须复核：

1. 将固定静态快照放入 `production_releases.py`，完整校验版本、时段、registry、states 和 context；正式快照仍为空、未初始化，无调用者替换入口。
2. manifest 绑定稳定实现提交 I、固定计算闭包及预定快照版本；随后只提交静态 trust 得到登记提交 H。I 必须是 H 的祖先，且每个闭包文件与 I 及实际加载内容一致。仅排除数据型 trust 文件；manifest 不绑定最终 trust 字节或 H，避免自引用。运行回执另记 H、I 和 trust 来源/摘要，Git blob 与原始字节域分开。
3. 先验证可信来源、完整结构和合法时间格式，再在共享锁内持久观察新版水位；随后判断具体 release。新版即使 revoked、合法 unknown、已过期或未生效也保持水位。损坏快照不推进；同版本冲突、旧版本和持久化异常均拒绝。
4. revoked/unknown 拒绝路径仅允许维护状态目录、锁和水位，不读材料、不建 claim 或输出。active 后的材料失败不能回退水位；重复 active 可读取绑定元数据取得执行标识，但必须在 data/cost 和内核前拒绝，保留旧 claim/report。
5. 共享锁内重新读取可信快照、时钟和水位，核验版本、摘要、active 状态、manifest、全部时效及条件后独占创建并持久化 claim。授权判定点是 claim 持久化完成；拒绝后不回收。已持久观察的撤回先于 claim 则阻断旧执行；本设计不提供执行中的撤销，也不能感知未观察的未来撤回。
6. 必须在临时真实 Git 历史完成 I→封印 manifest/review→只登记 trust→新解释器正常 loader/main/原内核，生成96行/8汇总及已知非零成本；不替换信任、Git身份、准入或 claim 判定。另验新版拒绝后的旧版回滚、冲突、进程同步撤回及闭包/未登记 trust 变化。

`b213749` 的定点复核确认原两项问题已闭合，但发现耗时实现核验前取得的旧时刻可跨过到期点，仍消费并计算。该轮结论为 **Spec FAIL / Quality NEEDS_FIXES**。修复须在耗时核验之后重新读取时钟；维持持久化完成为授权点时，还须在完成后复核时效，若已到期则保留 claim、拒绝后续 data/cost。后续 `5e261e6` 已按上述要求修复，同一审核者最终 **Spec PASS / Quality PASS**；具体证据与保留条件见[模块审核记录](2026-11-05-t121-production-adapter-review.md)。
