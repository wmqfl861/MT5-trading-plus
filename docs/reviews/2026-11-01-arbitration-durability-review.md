## 2. H 线：发现与修复

| 编号 | 问题 | 本批处理 |
| --- | --- | --- |
| H-A01 | `_journal_state` 在确认 JSON 是对象前调用 `.get`；合法的 `[]`、`null`、布尔、数字、字符串都会使工具崩溃 | 先检查对象类型；保留损坏行并按原有零基行号记为 `torn@N` |
| H-A02 | `append_jsonl` 不修复上条记录缺少换行的边界，仲裁终态会与损坏尾部粘连；工具可能报成功却无法解除同一未决项 | 在持锁并核对原始字节未变后，必要时补一个换行，再经 `append_line` 持久化完整终态；不删改原损坏证据 |
| H-A03 | 先写终态、后写意图；意图落盘失败时，执行器可已读到终态并移除 journal 防线 | 新仲裁先恢复意图、最后写终态。意图失败不得写入新终态；终态写失败仍可重试 |
| H-A04 | 多个仲裁进程及 runner 可以并发读写同一个 journal | 仲裁持有与 runner 相同的账户身份锁及旧目录锁，顺序与 runner 一致；锁冲突立即拒绝，所有退出路径释放自己持有的锁 |
| H-A05 | 缺少网关配置时回退默认配置，可能读取并据此修复错误账户的本地状态 | 配置文件必须存在；缺失即失败，不构造默认网关 |
| H-A06 | 不完整挂单/持仓、NaN/Inf/负数量、错误方向或品种冲突可能进入仲裁意图 | 严格校验；本 magic 有挂单时拒绝仲裁；只接受已确认 DEMO 身份，并在临界区内复查身份 |

新提交顺序：

```text
校验输入与 DEMO 账户身份
→ 取得账户身份锁 + 旧目录锁
→ 复查账户身份、读取 journal
→ 核对挂单/持仓并构造有效意图
→ 再查身份、挂单与 journal 原始字节
→ 持久化意图
→ 最后追加独立、可解析的终态记录
→ 写审计告警；保持现有 halt/pause/killSwitch 不变
```

旧版本已经写下的 `arbitrated:` 终态不删除、不改写；只允许相同 decision_id、
status、reason 的重试修复意图。已有普通执行终态或不同结论/原因一律拒绝。

**测试语义纠正：** 旧测试曾要求“意图写失败后终态已存在”。该断言固化了危险
提交顺序，本批替换为“新仲裁的意图写失败时仍是未决、无新终态”；同时另保留
旧版本终态的严格幂等恢复测试，不通过放宽业务断言让测试变绿。

## 3. 操作流程更新（覆盖 demo-runbook §5.4 的相应旧说明）

仅设置 killSwitch 并不等于 runner 已停止。仲裁前必须保持禁止开仓，并在维护
窗口确认目标 runner 退出。工具必须能够取得两类运行器锁，否则直接拒绝；
不得删除锁文件、修改环境变量或更换数据目录以绕过锁。新锁不声称覆盖另一个
操作系统用户、另一台机器或不遵守身份锁的旧版本跨目录进程，维护时必须排除
这些并发写者。

操作员仍须独立核实账户、品种、具体请求及券商历史事实。本地 journal 尚无
不可伪造的账户绑定，因此“DEMO 身份有效”不能替代“这是该 journal 所属账户”
的人工确认。程序的锁与校验不是券商侧原子事务，也不能阻止外部手工交易。

工具成功后不自动清除 halt、pause 或 killSwitch；完成全账户对账、确认无其他
未决项后再人工恢复。写入失败时保持停止状态，检查文件与日志后重试。若终态
写入已部分发生而 fsync 报错，不猜测事务失败或成功，重读 journal 后按精确
幂等规则处理。
