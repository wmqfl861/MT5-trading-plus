# 第三轮审核报告（2026-10-25）

审核范围：`main` 截至 `6e155a7`（P0 收尾 / P1 / P2 / P3-A 层，367 个测试）。
重点是本轮新增的 `mt5quant`（成本、策略接口、A 层引擎、报告、截断测试）、
`mt5data` 的 tick / 质检 / 重采样 / 锁箱 / 调度，以及仓库公开后的安全状态。
网关交易核心（`mt5gw`）经前两轮修复，本轮只复核了与新功能相关的改动。

## 结论

- **研究层有 1 个 Critical 和 3 个 High 级缺陷，均已在本轮直接修复**（提交 `045bffe`）。
  最严重的是回测引擎把"价格差 × 手数"当成账户货币：1 手黄金涨 $10 记为 +10
  （真实 +$1,000），一旦配置了佣金或隔夜费，盈利单会被算成亏损，收益率、回撤
  全部失真。修复前不能用这个引擎做任何策略选择。
- **安全有 1 个必须马上处理的问题**（S1）：仓库已公开，git 历史里有交易主机的
  公网 IP、MCP 端口和早期令牌，而 MCP 仍是明文 HTTP 对公网开放。
- 数据层（K 线库、质检、重采样、时段）质量高，测试扎实；tick 库的存储布局
  在深度回补前需要改（R3）。
- 待修问题共 16 项（R1–R16），已写进下一轮施工计划
  `docs/superpowers/plans/2026-10-25-review-fixes-p3b-p4.md`。

## 待修问题（按严重度）

### 安全

**S1 公开仓库泄露主机信息，MCP 仍是明文 HTTP（Critical，需用户决策）**
- 事实：仓库为 public。`6e155a7` 只把**当前文件**里的公网 IP 和模拟账号换成占位符，
  更早的提交里仍有：服务器公网 IP（8 处）、MCP 端口 47621、模拟账号 login、
  `9eccfc8` 提交过的 `mcp.json`（含当时的令牌，据第一轮报告已轮换）。
  第二轮报告的 I13（明文 HTTP 跨公网）至今未修。
- 风险：任何人都能从 GitHub 找到这台跑 MT5 终端的主机地址和 MCP 端口；
  明文传输的 Bearer 令牌可被链路窃听后重放；拿到令牌就能读全部行情库并消耗主机资源。
- 处理（按顺序）：
  1. 立即把 MCP 的公网监听收回：`mcp.json` 的 `host` 改回 `127.0.0.1`，远程 agent 改走
     SSH 隧道 / WireGuard / Tailscale；做不到就至少在 Windows 防火墙把该端口限制为远程
     agent 的固定 IP。
  2. 轮换 MCP 令牌（按已泄露处理）。
  3. 检查这台主机的 RDP：不要暴露公网，或限制来源 IP，开启 NLA 与强密码。
  4. 仓库可见性二选一：改为 Private（最简单），或用 `git filter-repo` 清理历史后强推
     （改写历史，所有本地克隆需重新 clone）。**改写历史必须由用户决定。**

### 研究层（影响策略选择的正确性）

**R1 点差模型把近期 tick 的绝对点差套用到全历史（High）**
- 位置：`costs/spread.py`（价格单位的 p90）、`scripts/run_backtest.py::build_costs`。
- 问题：tick 只有最近几周，点差以价格单位存储。黄金从 2014 年的约 $1,300 涨到现在，
  点差绝对值大致随价格放大；用今天的点差回测 2014–2020 年会把成本高估数倍，
  BTC 同理。结论会系统性偏向"早年不可交易"。
- 修复：点差改为相对口径（p90 of `(ask−bid)/mid`，按小时），回测时乘以当时价格；
  或用 K 线自带的 `spread` 字段（bar 内最小点差，全历史都有）按小时倍数校准。
  成本接口需加 `when`/`price` 参数（计划 T3）。

**R2 锁箱 cutoff 按序列各自计算（High）**
- 位置：`mt5data/lockbox.py::compute_cutoff`（历史 >5 年锁 12 个月，否则 6 个月）。
- 问题：不同品种的锁箱起点可能不同。跨品种研究时，未锁品种在另一个品种锁箱期内的
  行情会泄露那段时间的市场状态（四个标的之间有美元、风险偏好等相关性）。
  另外 G5"只能用一次"目前没有任何登记。
- 修复：全部品种、全部周期用**同一个固定 cutoff**（取最保守者），一经写入不得前移；
  锁箱使用记录进试验台账（计划 T2、T11）。

**R4 隔夜费与佣金还没接入真实规则（Medium）**
- 快照缺 `swap_mode`（点数/货币/利率等计费口径）和 `swap_rollover3days`（三倍日）；
  Exness 不少账户是免隔夜费状态，佣金取决于账户类型（标准/Raw/Zero/Pro）。
- 修复：快照补字段；用模拟盘真实成交记录（deal 的 commission/swap）校准，
  再由快照生成 `SwapModel` / `CommissionModel`（计划 T5）。

**R5 "服务器时间 = UTC" 是隐式假设（Medium）**
- 时段、周末缺口、周五强平、按小时取点差都把 bar 时间当 UTC 用。Exness 服务器是
  GMT+0 所以目前成立；换经纪商（多数是 GMT+2/+3）会全部静默错位。
- 修复：配置显式声明 `server_utc_offset_hours`（默认 0），刷新与回测启动时用
  `data/server_clock.json` 的最新有效样本校验，不符即拒绝运行（计划 T6）。

**R6 缺"窗口不变性"检查（Medium，P4/P7 前必须有）**
- 截断测试只证明"前缀信号与全量一致"。实盘信号运行器只会用最近 `lookback_bars`
  根计算信号；EMA、Wilder 类长记忆指标在"窗口计算"和"全史计算"下数值不同，
  导致实盘信号与回测不一致。
- 修复：G0 增加窗口不变性测试——任取 t，用 `bars[t-L+1..t]` 算出的末位信号必须等于
  全量信号的第 t 位；不等就要求加大 `lookback_bars`（计划 T12）。

**R7 保护性出场后同向信号立即重入（Medium）**
- 引擎是"目标仓位"语义：止损后信号若仍为 1，下一根开盘就重新入场。ATR 止损类
  策略会反复"止损—重入"，成本被放大。
- 修复：`ExitRules` 增加 `reentry="immediate" | "after_signal_change"`（计划 T7）。

**R8 周五强平对 H4/D1 会提前一整根（Low）**：按 bar 收盘时刻判定，D1 会在周四收盘就平仓。
限定 `week_close_exit` 只用于 ≤H1，或在文档里写清。

**R9 按收盘价出场的 `exit_time` 记的是 bar 开盘时刻（Low）**：影响隔夜费边界与持仓时长统计。

**R16 引擎不模拟保证金与爆仓（Low）**：手数与本金不匹配时权益会变负，`pct_change` 得到的收益率、Sharpe、回撤全部失真。至少要在权益 ≤ 0 时停止开仓并在报告里标记。

**R10 MCP `list_series` 未按锁箱钳制 rows / last_time（Low）**：只泄露元数据，不泄露价格。

**R11 刷新的重叠证明只比对时间，不比对 OHLC（Low）**：经纪商修订历史时会被静默覆盖，
建议把重叠段差异写进日志。

**R12 `cost_audit.py` 合约大小缺失时静默按 1.0（Low）**：与 `run_backtest.py` 一致改为报错。

**R13 MCP 把品种名转成大写（Low）**：README 说保留大小写；Windows 文件系统不区分大小写所以无碍，
迁到 Linux 会找不到序列。

### 数据与运维

**R3 tick 库是单文件（Medium，深度回补前必须改）**
- 位置：`mt5data/ticks.py`。每次刷新都把整个 tick 历史读进内存、去重、排序、整表重写；
  黄金一年的 tick 是数千万行，几年后单次刷新要数 GB 内存。回补循环里 `pd.concat`
  逐块累加是 O(n²)；`arr.tolist()` 构造 DataFrame 很慢。
- 修复：按月分区 `ticks/{SYMBOL}/{YYYY}/{MM}.parquet`，刷新只动当月文件；
  回补用列表收集、最后一次 concat；直接 `pd.DataFrame(arr)`（计划 T4）。

**R14 定时刷新与将来的实盘进程共用一个 MT5 终端（Ops）**：P7 设计时要安排单写者或错峰。

**R15 没有 CI（Process）**：仓库是公开的，GitHub Actions 免费；建议 windows-latest + Python 3.12
跑全量 pytest，每次推送自动验证（计划 T8）。

## 做得好的地方

- 成本拆分口径清楚：点差每个来回只收一次，滑点恒为不利方向，隔夜费恒为成本方向，
  测试全部用手算数字钉死。
- 锁箱的"显式越界报错、绝不静默截断"语义正确，MCP 的三个读取路径都已钳制。
- 质检把常规休市按交易所本地小时分桶，正确处理了夏令时切换周（10/25 欧洲、11/01 美国）。
- 重采样与经纪商原生周期逐根对账，价格不一致即失败。
- tick 刷新的"重叠证明"和 K 线一致，接续不上就拒绝写入。
- 网关交易核心：保险丝、账号钉死、order_send 在同一次持锁内完成，仍然是全库最扎实的部分。
