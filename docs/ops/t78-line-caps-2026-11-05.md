# T78 号段日亏子上限

本模块接通离线工程风险链路，不表示真实 Demo 上线、研究或维护条件已放行。现有运行配置及部署不随本变更调整。子上限为可选项；省略 `line_caps` 时，旧账户上限和闸门流程保持。

## 配置示例

以下为公开合成示例，在既有 risk TOML 顶层保留账户上限，并追加两个表；其余既有必填字段仍需提供。示例不是默认值，也不会自动写入任何运行配置。

```toml
daily_loss_cap_usd = 500.0

[[line_caps]]
name = "H"
magic_min = 902000
magic_max = 902999
daily_loss_cap_usd = 250.0

[[line_caps]]
name = "P"
magic_min = 903000
magic_max = 903999
daily_loss_cap_usd = 250.0
```

`RiskConfig.line_caps` 默认为空元组，元素为 `LineCap`。名称只允许字母、数字、下划线和短横线，忽略大小写不得重复；magic 必须为非负有符号 64 位整数，闭区间不得倒置或重叠。金额须为有限正数，bool 不作为数字接受。

## 实际裁决路径

- 日界沿用 `daily_pnl` 的 UTC 自然日。交易类 deals 计 `profit + commission + swap + fee`；持仓计 `profit + swap`，按 magic 闭区间归属。出入金不计，账户须为 USD，不做币种换算。
- `RiskGate` 优先检查 `halt.json` / `killSwitch` 与独立 `risk_health`，避免先进入账户 IPC。启用 caps 后，从同一次账户 snapshot 的当日 deals 与 positions 同时计算账户和各线损益；没有 snapshot 接口时沿用账户服务查询。
- 账户总损益 `<= -500` 的示例阈值仍优先：先写既有带编号 `flatten.json` 与 `halt.json`。线 pause、线状态损坏、合约/报价错误不能掩盖已知账户触限。
- `RiskProcess.run_cycle` 与同步 `check_order` 都实施子限额。直接调用同步入口时，`RiskState.line_pnl` 必须提供配置线的净损益，`snapshot_magics` 传同快照可见 magic；缺失/非法数据拒开该线。纯 `check` 也裁决瞬时线阈值，但跨重启锁存由 `RiskProcess` 负责。
- 子线总损益 `<= -250` 时只拒该线后续开仓，另一线仍可开；不生成子线 flatten 或全局 halt。`LiveExecutor` 的平仓及反手平仓腿沿既有路径执行。

## 当日锁存、所有权与对账

`line-cap-<name>.json` 是独立线锁存依据，记录 owner、line、magic 范围、cap、UTC day、ts 和 latched。当天亏损恢复也不解除，重启及后来加入的 magic 都读取同一线状态。首次锁存追加 `LINE_CAP` 告警；重复周期与同日重启不重复告警。fix1 在核验线状态后，先持久化当前触限，再处理任何兼容 pause 锁；pause 锁超时或读写失败不会丢失已观察到的首次触限。独立线状态自身写失败则拒开并返回可识别的状态错误，不报告锁存成功。

`pause-<magic>.json` 是兼容输出，`reason="line_cap"`、`owner="risk_line_cap"`，包含同一 line/date/范围身份。已登记或账户快照可见的本线 magic 都尝试写入；已有人工、未知、损坏或正在生效的对账暂停保持原样。线锁存不依赖兼容输出是否能占用该文件。

`reconcile.write_pause` 一致时保留线 pause。发现新的真实 mismatch 时，先写独立 `reconcile-block-<magic>.json`（owner=reconcile、paused=true），再尝试更新兼容输出。即使人工文件是 `paused=false` 且不可覆盖，Gate 也在 caps 开启/关闭两种路径上读取自有阻断并拒开。对账一致只清可验证为 reconcile 自有的阻断；坏形状、未知 owner、不可读阻断保留且拒开。创建、更新和清理与兼容 pause 共用同一个 `pause-<magic>.json.lock`，复用原子写，写失败传播而不声称成功暂停。

可识别的线 pause 可在真实 mismatch 时改由 `reconcile_mismatch` 持有，独立线锁存继续当天阻止整线开仓；次日仅清线自己的标记，不删除对账阻断。既有可识别对账暂停仍可在对账一致后解除，人工原文件始终保留。

下一 UTC 日首次成功检查，仅解除身份、形状及日期均可验证的旧线状态和旧线 pause；其他暂停保持。未来日期、未知字段/owner、损坏状态保留并拒开；配置身份改变也按未知状态处理。不得靠手动改 day/owner 绕过日锁存。

读改写复用 `fileio.file_lock` 与 `write_json_atomic`：每线锁串行化 monitor/gate，每个 pause 路径锁串行化风控和对账，ownership 在锁内检查。fix2 的 Gate 在同一 `pause-<magic>.json.lock` 短临界区内一致读取 reconcile block 与兼容 pause，避免原因从人工暂停交接给对账阻断时跨时点拼出“允许”；锁超时和读取失败均拒开。该锁只覆盖这两个文件读取，不跨账户/行情 IPC 或下单持有，账户总额优先和平仓豁免保持。合成测试用 Event 控制真实读取后的合作写者交错，覆盖 caps 开/关、锁超时、短持锁边界与账户 cap 全平。人工工具若并发修改同一文件也必须遵守该锁约定；任意绕过锁的外部裸写不在协作写入保证内。

## Paper 原始字段边界（fix1）

初版 T78 未修改 `paper.py`，其既有反序列化会把 `true` 转为 `1`、字符串/浮点强转为整数，并把缺失 magic 默认成 `0`，使下游严格 magic 校验无法识别原始异常。fix1 仅在 positions/deals 两个反序列化点，转换前要求原始 magic 是非 bool 的非负有符号 64 位整数；缺失、字符串、浮点和越界值抛 `DataUnavailableError`，真实 `PaperAccountView`、监控快照入口与 Gate/Executor 按数据不可用拒开。合法人工 magic `0` 与 H/P 号段保持；不修改撮合、金额或成交算法。
